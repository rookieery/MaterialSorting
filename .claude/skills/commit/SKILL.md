# Git Commit Skill

## 上下文
- 风格参照：!`git log --pretty=format:'%s' -10`
- 当前状态：!`git status --short`
- 本仓库提交信息惯例（从 git 历史总结，必须遵守）：
  - **单行超长中文信息，无 body、无 AI 署名脚注**
  - 格式：`<type>: <主题> - <详情>`（type 后用半角冒号+空格）
  - type 取值：`feat` / `fix` / `docs` / `refactor` / `test` / `chore`
  - 详情结构（用 `；` 和 `。` 串联）：**背景与动机 → 关键依据/决策 → 改动点清单 → 验证结果 → 文档同步**
  - 写实、密集、具体：带文件名、函数名、参数值、测试数字（如「vitest 52 文件 791 全过」「E2E 11/11」）、口径与红线（如「info_table=None 输出逐字节不变」）
  - 决策类改动要写**为什么**（用户反馈/版师定案/实测数据），不只写改了什么

## 执行步骤

1. **收集证据**：
   - `git status --short` 看全部改动文件；
   - `git diff` + `git diff --cached` 读具体变化（新增文件用 Read 看内容）；
   - 结合**当前会话上下文**——本会话里做了什么、为什么做、用户说过什么要求，这是「关键依据/决策」段的主要来源；diff 只作证据核对，不凭空编造。

2. **生成提交信息**：按上述惯例写单行信息。主题短语概括这次改动（如「通用标识优化」「PLT 表格汉字逐字上下颠倒」）；详情按结构展开，改动点多时逐项用 `；` 分隔。

3. **暂存并提交**：
   - 若用户在 `/commit` 后附带参数（指定文件、指定主题等），按参数执行；
   - 否则 `git add -A` 暂存全部改动；
   - 提交用 heredoc 防引号转义问题：
     ```bash
     git commit -m "$(cat <<'EOF'
     <提交信息>
     EOF
     )"
     ```

4. **汇报**：提交成功后简洁展示 commit hash + 提交信息；若改动涉及文档同步但本次没同步，提醒可跑 `/sync-docs`。

## 注意事项
- 工作区干净（status 无输出且无未跟踪文件）时不提交，直接告知「没有可提交的改动」。
- **只 commit 不 push**，除非用户明确要求。
- 提交信息必须与 diff 实际内容一致，不确定的验证结果（本会话没跑过的测试）不要写进「验证」段。
- 临时文件、调试产物若被 `git add -A` 带入且明显不该入库（如本地截图、临时脚本），先向用户确认再决定是否排除。
