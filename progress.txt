**关键设计决策**：
- **Path A 全复用**：服务端直接跑 `export_dxf` 切单裁片 + `load_nest_pieces` 全码加载，而非另写「上传母版 → NestPiece 直转」。理由：`ptype` 来自单裁片文件名（`{ptype}_{size}.dxf`），由 `assign_group_no` + `GROUP_NAMES` 在导出时赋值，跳过 `write_piece_dxf` 会丢失 ptype 映射。复用全管线零风险。
- **全码 sizes 来自母版实测**：`sorted({p.size for p in pieces if p.size is not None})`，M1787 实测 [28-38] 11 码（vs `DEFAULT_SIZES` 8 码跳 32）。**不沿用 `DEFAULT_SIZES`**。
- **GATE_MM 别名导入**：`from ..nesting_bounds.load_pieces import GATE_MM as NEST_GATE_MM`。`server.py` 顶层已有 `_DOC, GATE_MM, PIECES = load_pieces()` 从既有 intermediate 读 GATE_MM（1980.0）；写回新 intermediate 时用 `NEST_GATE_MM`（load_pieces 模块的源常量 1980.0），而非既有 intermediate 的值——避免「写回时把既有 intermediate 的可能脏值扩散」。
- **`filename` 可选不强制**：AC1 说入参 `{doc_id}`，但 source 字段需要「上传文件名」。折中：payload `{doc_id, filename?}`，filename 缺省用 `<doc_id>.dxf`。前端 commit 按钮（TODO）会有 uploadStore.filename 直接传；curl 测试可显式传 filename 覆盖。**不改 US-004 parse-dxf 添加 sidecar**——保留 US-004 行为不变。
- **idempotent 临时目录**：每次 commit 先 `rmtree` 再 `mkdir`，避免旧文件残留污染（M1787 假设一码一片型唯一；新款若违反，文档化为 open question）。
- **`.bak` 单份**：再 commit 会覆盖 `.bak`——保留最近一次写回前快照足够回滚。多版本备份非 v1 目标。
- **不 auto-reload PIECES**：`server.py` 顶层 `PIECES = load_pieces()` 是 import 时一次性加载；commit 后 intermediate 文件已更新但内存 `PIECES` 不变。**v1 TODO 随排料页改造补 reload 端点或重启策略**（AC6 明确 deferred）。
