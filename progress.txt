## US-026 WS /ws/solve 支持 stop 消息（持续读 + 进程终止 + 协议扩展）— 2026-08-12

**改动文件**：
- `materialSorting-server/src/materialsorting/web/server.py`：ws_solve 从「只读一次 start」改为 write loop 内联 + read loop 后台 task 双向并发；build_instance 移入子进程（改调 solve_with_callback_proc）；stop → terminate+join → 直发 stopped → 投 SENTINEL；WebSocketDisconnect → terminate+join 防孤儿（修旧 bug）；_terminate_solve_process 幂等封装；finally 显式 ws.close()。
- `materialSorting-server/src/materialsorting/web/solver.py`：solve_with_callback_proc 新增 on_process 回调（子进程 start 后立即回调交出 Process 句柄）。
- `materialSorting-web/src/types/ws.ts`：新增 StopPayload / ClientMsg 联合 / StoppedMsg / ServerMsg 增 StoppedMsg。
- `materialSorting-server/tests/test_ws_stop.py`：新增 3 项 WS 测试（stop+stopped / 断连清理 / 正常 final 回归）。
- `materialSorting-server/pyproject.toml`：dev deps 加 httpx（TestClient WS 测试依赖）。
- `.docs/technical/agent-api-reference.md` / `agent-file-map.md` / `agent-component-map.md`：WS 章节、solver 表、ws.ts 描述、关键不变量同步。
- `web/AGENTS.md`：新增 US-026 关键约定段。

**关键实现决策**：
- write loop 内联（主流程）+ read loop 后台 task（非 asyncio.gather）：gather 在 write loop 先完成时 hang 等 read loop（TestClient receive_json 不响应 cancel），inline 方式让 write loop 收 SENTINEL 后直接 break → finally 兜底。
- stopped 由 read loop 直发（不经 queue）：避免 stop 后残余 frame 在 queue 里排在 stopped 前面 → 客户端先收一堆 frame 再收 stopped。
- finally 显式 `await ws.close()`：TestClient（anyio portal）下 endpoint 返回不会自动让 client 端 receive_json 抛 disconnect，必须显式 close。
- 不 await read_task：TestClient 下 ws.receive_json() 阻塞在线程安全队列上，task.cancel() 的 CancelledError 无法投递，await 会永久挂起。
