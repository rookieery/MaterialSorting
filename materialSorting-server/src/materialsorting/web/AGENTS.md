# web — Agent 速查

> FastAPI + WebSocket 工作台（最上层）。可 import 全部下层（dxf_parser / nesting_bounds / nesting_engine）+ `paths`；下层**禁** import 本包。
> 改前先看 `.docs/technical/agent-api-reference.md`（HTTP/WS 契约）+ `.docs/technical/agent-file-map.md` web 章节。

## 启动 / 校验

```bash
python -c "from materialsorting.web.server import app"                # 导入冒烟（含路由表打印）
ms-web                                                                 # 启动 uvicorn :8000（console_script）
python -m materialsorting.web.server                                   # 等价（无 console_script 也能跑）
curl -X POST http://127.0.0.1:8000/api/parse-dxf -F "file=@<dxf>"      # US-004 上传解析
curl http://127.0.0.1:8000/api/ptypes                                  # US-020 裁片 g 码代表（US-001 v2 键 = label）
curl -X POST http://127.0.0.1:8000/api/edit-polish -H "Content-Type: application/json" \
     -H "X-Session-Id: <sid>" -d '{"placed":[{"id":"g01_30","rotation":0,"translation":[0,0]}]}' \
                                                                      # prd-edit-polish US-002 编辑「智能微调」（placed 随 body；报告口径 = 物理毛版
                                                                      # 轮廓 ≠ 画布 erode 红字口径，差异注记见 agent-api-reference.md 专节 ⚠️；
                                                                      # US-005 可选 "compact":true → 引擎压缩回收档（缺省 false additive））
```

> **intermediate 由 Web 上传母版 commit 生成**（`server.py` 启动期 `_reload_pieces_state()` 在 import 时读 `pieces_intermediate.json`；缺失不崩但 `_PIECES_STATE` 为空 dict，`/ws/solve` 报「排料数据为空」、`/api/ptypes` 返回 `{representatives:{}}`，前端上传母版 commit 成功后自动 reload 填入）。`materialSorting-web/static/` 也需 `npm run build` 一次让 mount 不空（dev 模式 Vite proxy 不依赖 build 产物，但 FastAPI mount 空目录会报错）。

## US-004 /api/parse-dxf 关键约定（实现方/调用方必读）

- **multipart 依赖 `python-multipart`**：已在 `[web]` extra（`pyproject.toml`）。否则 FastAPI `UploadFile = File(...)` 启动即报 `AssertionError`。
- **落盘路径**：`paths.OUT_DIR/uploads/<doc_id>.dxf`（`doc_id = uuid.uuid4().hex`，32 字符无横杠）。**禁硬编码** —— 用模块级常量 `UPLOADS_DIR = Path(paths.OUT_DIR) / 'uploads'`。
- **CPU 解析走 executor**：`loop.run_in_executor(_executor, _parse_dxf_sync, str(dest))` 复用 6-worker 线程池（与 `/ws/solve` 同池）。母版深度解析 ~1-2s，不阻塞事件循环。
- **错误码口径**：扩展名非 `.dxf`→400；超 `UPLOAD_MAX_BYTES=20MB`→413；ezdxf/collect 异常→422（中文错误信息）。**200 / 400 / 413 / 422 全部走 JSONResponse**（与 `/export` 一致），不抛 `HTTPException`。

## US-025 关键约定（求解进程化 solve_worker + solve_with_callback_proc）

- **背景**：sparrow 编译为 Rust `.pyd`，`instance.solve()` 是原生阻塞调用；全包 grep `cancel|abort|stop|pause|kill|terminate` = 0 匹配，`ProgressQueue` 仅只读 `drain()`，无任何中断 API；`threading.Thread` 无法安全终止原生代码线程；唯有 `Process.terminate()`（Windows 调 `TerminateProcess`）可靠。
- **spyrrow 对象不可 pickle** → `build_instance` 必须在**子进程内**执行（`solve_worker` 顶层函数 + 参数全 JSON 可序列化），只把 pid_meta/frame/final/error 经 `multiprocessing.Queue` 传回主进程。
- **`solve_worker` 必须 pickle-safe**：顶层函数、无闭包、参数全部 JSON（list/dict/float/int/str）。延迟 `from .solver import build_instance` 放函数内（避免主进程 `from .solve_worker import solve_worker` 时强制 import sparrow_baseline）。
- **density 双口径换算位置**（关键不变量 #1）：**主进程**在收到 frame 时执行 `density_sparrow ← density; density ← total_area/(width*gate_mm)`（输入幅宽口径，2026-08-28 版师定案起单一口径不再 min(gate,1910)；换算集中在 `_apply_density_dual` 函数内 = web/CLI 所有调用方自动一致）；`total_area` 由 manifest 投递带入主进程。不在子进程做。换算逻辑与公式同旧 threading 版（仅分母口径更新），执行位置不变。
- **终止安全（防死锁，风险 R1）**：`process.terminate()` 后必走 `result_queue.cancel_join_thread()`（停 background feeder thread）+ 限时 drain（循环 `get_nowait()` 累计 ≤50ms 或 Empty 即 break）+ `process.join(timeout=5)`；join 超时再 `kill()` 兜底。**绝不**无限阻塞 join。
- **循环退出条件**：`while True: get(timeout=drain_interval if alive else 0.05)`，`queue.Empty` 且 `not alive` 时才 break —— 子进程死后继续 drain 完 queue 残余（避免漏 final）。
- **子进程异常 3 类**：①`build_instance` 抛错 → 子进程投 `{kind:error,message}` 后正常退出（exitcode=0），父进程收到 error 退出；②`solve` 崩溃 → 同理；③子进程被外部 kill / 崩溃未投 error → 父进程 `process.is_alive()=False` 后 drain 完 queue 退出，`err='worker process exited unexpectedly (code=<exitcode>)'`。
- **旧 `solve_with_callback` 保留不删**（过渡期），US-026 已切换 `ws_solve` 调用方到 `solve_with_callback_proc`。
- **测试**：`materialSorting-server/tests/test_solve_proc.py` ≥4 项（正常求解 / terminate 5s 内返回 / build_instance 抛错 / 外部 kill 不 hang + solve_worker 可 pickle）。Windows multiprocessing：测试不创建模块级 Process；conftest 加 sys.path 让 `from materialsorting...` 在未 `pip install -e .` 时也能跑。

## US-026 关键约定（WS /ws/solve 支持 stop + 进程终止 + 协议扩展）

- **ws_solve 双向并发**：write loop 内联（主流程）drain asyncio queue → `ws.send_json`（manifest/frame/final/error）；read loop 后台 task 持续 `await ws.receive_json()` 收 `{action:'stop'}` / WebSocketDisconnect。
- **stop 处理**：read loop 收 `{action:'stop'}` → `state_box['stopped']=True` → `_terminate_solve_process(state_box)` → `await ws.send_json({type:'stopped'})` 直发 → `queue.put_nowait(_SENTINEL)` → return。stopped 是客户端收到的最后一条业务消息（write loop 在 `stopped` 标志置 True 后丢弃残余 frame）。
- **客户端断开清理（修旧 bug）**：read loop 捕获 `WebSocketDisconnect` → `stopped=True` → `_terminate_solve_process(state_box)`（terminate+join 5s）；旧版 `except:pass` 静默忽略断开 → 求解线程跑满预算（120s+）占用线程池。
- **`_terminate_solve_process(state_box)` 幂等封装**：alive → `terminate()` → `join(timeout=5)` → 仍活 `kill()` → `join(timeout=1)`。read_loop（stop/断开）、write_loop send 失败、finally 兜底三处调用。
- **`on_process` 回调（US-026 新增）**：`solve_with_callback_proc` 新增可选 `on_process` 参数 —— 子进程 `start()` 后立即回调，把 `Process` 句柄交给 `ws_solve` 存入 `state_box['process']`，供 stop/断开时 terminate。旧调用方不传则不回调（向后兼容）。
- **finally 显式 `ws.close()`**：write loop break 后 finally 块 cancel read_task + `await ws.close()` + terminate process。`ws.close()` 在 TestClient 下必须显式调（Starlette 不会在 endpoint 返回后自动关 WS 到 client 端 receive_json 抛 disconnect 的程度）；uvicorn 下也安全（幂等）。
- **不 await read_task**：TestClient（anyio portal）下 `ws.receive_json()` 阻塞在线程安全队列上，`task.cancel()` 的 CancelledError 无法投递；`await read_task` / `wait_for(read_task)` 会永久挂起。uvicorn 生产环境 cancel 正常生效，ws_solve 返回后 FastAPI 关 WS 让 read_loop 自然退出。
- **协议扩展（types/ws.ts）**：新增 `StopPayload={action:'stop'}`；`ClientMsg=StartPayload|StopPayload` 联合；新增 `StoppedMsg={type:'stopped',reason:'user_requested'}`；`ServerMsg` 联合增 `StoppedMsg`。向后兼容（旧前端不发 stop，后端不发 stopped）。
- **测试**：`tests/test_ws_stop.py` 3 项（start→frame→stop→stopped+WS 关闭 / start 后直接断连→进程数回落 / 不发 stop 正常求解收 final）。用 `starlette.testclient.TestClient`（需 `pip install httpx`）。小问题（16 片）exploring 阶段每 ~3ms 吐帧 → 3s 预算积攒 ~800+ frame，测试用 deadline 循环非固定计数。

## 多会话 US-001 关键约定（sessions.py + POST /api/session；2026-08-27）

- **背景**：ms-web 原是「单文档单例」——`_PIECES_STATE` 进程级一份，多端（本地 :5173 / 隧道 8081）同时使用时任一端 commit 即覆盖所有人当前文档（静默串台）。会话 token（sid）机制按端隔离；本 story 只落**注册表与生命周期**，commit 双写（US-002）/ 读路由接入（US-003）/ 策略会话化（US-004）/ 前端接入（US-005）随后。
- **单一解析函数**：sid → 会话归属只走 `sessions.registry.resolve(sid, create=?)`，路由不得自行翻注册表。缺省（None/空串）→ `DEFAULT_SID='default'`；`'default'` 含非 hex 字符，与 uuid4 hex sid 结构性不可碰撞。
- **default 豁免三件事**：容量上限、空闲过期、墓碑 —— 且不占 `MS_SESSION_MAX` 名额。其 pieces 快照 = `runtime._PIECES_STATE` **同一 dict 对象**（runtime 只原位 clear+update 从不 rebind → commit reload 自动同步；`tests/test_web_sessions.py` is 判等锁死）。无 sid 请求行为与单文档时代逐字节一致（旧测试零改动回归的根基）。
- **错误类型即 HTTP 语义**：`SessionError` 族自带 `status/code/payload()`（`InvalidSidError` 400 无 code / `SessionExpiredError` 401 `session_expired` / `SessionLimitError` 429 `session_limit`，后者文案随 `max_sessions` 插值）。路由捕获后 `JSONResponse(e.payload(), status_code=e.status)` 一行映射；`code` 键 additive，旧前端可忽略。
- **惰性过期 + 扫描兜底**：请求时惰性检查（超时当场逐出为墓碑 → 401）+ 30s daemon 扫描线程（server.py 文件尾 `session_registry.start_scanner()` 启动；daemon=True）。**扫描必须跳过 `ws_open>0`**（WS 连接钉住，求解中不误杀）；已死会话不再发请求，容量名额只能靠扫描回收。扫描线程异常只 warn 不崩。**alive hook（2026-08-30）**：`_is_expired` 三段短路（WS 钉住 → TTL 未超 → `_pinned_by_hook` 问 hook），hook 只在本来就要过期时才被调（新鲜会话零开销）；hook 在持 `registry._lock` 上下文内执行 —— 契约 = 只许纯内存 dict 读写 + 非阻塞探测（`Popen.poll()`），禁止文件 IO/锁获取，异常吞掉当 None；生产方 = strategy.py `_run_alive_hook`（run 存活钉住 + 终态宽限窗；**2026-09-04 起 server.py 文件尾 `edit_hold.install` 把它包成组合体**——编辑排料钉住 + strategy 委派保留，任一豁免源给出未来时间戳即钉住，结构哨兵在 tests/test_web_edit_hold.py），`reset()` 不清 hook（进程级接线）。
- **墓碑**：逐出丢全部状态只留 `{sid, ts}`，FIFO ≤128、存活 1h；墓碑命中 → 401 不静默重建（防过期 sid 被当新会话）。墓碑 1h 过期或 FIFO 淘汰后该 sid 视为全新可正常新建。合法但从未注册的 sid 在读路径（`create=False`）同过期语义 401（服务重启丢内存场景）。
- **sid 字符集单一真相源 `SID_RE`**（`^[0-9A-Za-z]{1,128}$` = doc_id 同规则）在 sessions.py；server.py `from .sessions import SID_RE as _DOC_ID_RE` re-export（同一编译对象，US-010 commit 校验继续用旧名）。
- **测试隔离**：`tests/test_web_sessions.py` autouse fixture 先 `stop_scanner()`（防真实扫描线程在 monkeypatch 时钟窗口内并发逐出 → flaky）再 `reset()`；TTL/墓碑全用可注入 `_FakeClock`（模块导出，测试/冒烟共用），零真实墙钟等待。会话状态全内存无磁盘态，天然与 `out/` 数据隔离。
- **env 旋钮**：`MS_SESSION_MAX`（缺省 4）/ `MS_SESSION_TTL_SEC`（缺省 600）；import 时解析，非法值 warn 回退缺省。

## 多会话 US-002 关键约定（commit 双写与会话绑定；2026-08-27）

- **双写口径**：`_commit_to_nesting_sync` 把同一 doc dict 写两文件，**顺序先 per-doc 后镜像** —— 主写 `uploads/<doc_id>_pieces/pieces_intermediate.json`（`_per_doc_intermediate(doc_id)` 单一真相源 + `PIECES_INTERMEDIATE_NAME` 常量；会话快照的数据源，多会话互不覆盖的磁盘锚点），镜像写 `paths.INTERMEDIATE`（单文档时代兼容面：无 sid 启动 reload / CLI 工具链 / 人工排查）。**镜像失败仅 warn**（stderr + 响应 additive `mirror_error` 键），不影响 per-doc 落盘、会话注册与 200 响应；`.bak` 备份行为保留在镜像侧（per-doc 目录随 commit 整体重写，天然 idempotent 无需 .bak）。
- **路由分叉（`commit_to_nesting` 读 `X-Session-Id`）**：带 sid → 会话解析**先行**（fail-fast：过期 401 / 超限 429 / 非法 400 都不跑 CPU 管线不落盘；`resolve(create=True)` —— 合法未注册 sid 可直接 commit 建会话，数据自带），commit 成功后 `_build_pieces_state(per-doc 路径)` 快照挂到该会话（`st.state` 赋值 + `st.doc_id = doc_id`），**不触碰 default 内存**；无 sid → default 会话更新（现行为，`tests/test_commit_pipeline.py` 零改动回归）。
- **漂移语义（定稿）**：default = 最后**无 sid** commit 者，镜像 = 最后 commit 者，两者允许漂移（A 带 sid commit 后 default 可能还是旧 doc，镜像已是 A 的 doc）；`_PIECES_STATE` 与 default 会话 state 恒为同一 dict 对象（US-001 is 锁死不变量，commit 只 clear+update 不 rebind）。
- **`_reload_pieces_state` 缺省参数坑**：签名 `def _reload_pieces_state(intermediate_path: str = paths.INTERMEDIATE)` 的缺省值在 **import 时绑定**——monkeypatch `paths.INTERMEDIATE` 后裸调 `_reload_pieces_state()` 仍读启动期真实路径。路由层必须**显式传 `paths.INTERMEDIATE`**（调用时取模块属性）；`_build_pieces_state` 同款签名但 sid 路径恒传显式 per-doc 路径，不受影响。
- **per-doc 落盘布局（US-006 消费）**：`uploads/<doc_id>_pieces/` 内 = `{label}_{size}.dxf` × N + `pieces_manifest.json` + `pieces_intermediate.json` 三类；读路由按 sid 取会话内存快照（US-003），磁盘 TTL 清理按 `<doc_id>.dxf` + `<doc_id>_pieces/` 成对口径（US-006）。
- **测试**：`tests/test_commit_sessions.py` 9 例（双写逐字段一致 / 双会话隔离 / default 不动 + is 锁死 / 无 sid 回归 + 最后无 sid commit 者语义 / 过期 fail-fast 不落盘 / 非法 400 / 未注册 sid 建会话 / 镜像失败 warn-only）。

## 多会话 US-003 关键约定（读路由与 WS 接入会话；2026-08-27）

- **读路由单一解析点**：`routes_views._resolve_session_state(request)` —— `X-Session-Id` Header（strip 空串归 None）→ `session_registry.resolve(sid).state`（**读路径 create=False**：未知合法 sid（服务重启）同过期语义 401 不静默重建、不占新名额）。四个读端点（`/api/ptypes` GET、`/api/band-preview`、`/api/prefix-preview`、`/export` POST）全部走它，`SessionError` → `JSONResponse(e.payload(), e.status)`（401/429 带 `code`，400 无 code）fail-fast 先于业务校验/请求体解析。缺省 → default 会话（state 即 `runtime._PIECES_STATE` 同一 dict，无 sid 行为逐字节不变——`tests/test_band_preview_api.py` / `test_prefix_preview_api.py` / WS 协议存量测试零改动全绿）。
- **`/export` 过期 = JSON 非文件流**：会话解析在导出逻辑之前，401 `{code:'session_expired'}` 是 JSONResponse 而非文件下载（A 的 placed 匹配 A 的 `pieces_by_id`；pid 不在会话 → 400「均未匹配」）。
- **GET / no-cache**：`FileResponse(..., headers={'Cache-Control': 'no-cache'})` —— FastAPI FileResponse 缺省不发缓存头，浏览器启发式缓存会让部署新 bundle 后旧 index.html 引用已删 hash 资源（旧前端滞留 default 会话语义的迁移窗口）。带 hash 的 `/static` 资源自身可长缓存不受影响。
- **WS `?sid=` query（浏览器 WS 不能自定义 Header）**：accept 后立即 `ws_acquire(sid)`（resolve 语义 + `ws_open += 1`）—— 求解中（10-60 分钟）扫描线程对 `ws_open>0` 会话跳过逐出；**任何退出路径**（final/error 早退/stop/断开）经整函数 try/finally `ws_release` 减回（断开归零，之后才可被逐出）。
- **WS 错误帧契约**：accept 阶段会话解析失败 → `{'type':'error','message':e.error}` + 有 code 才加 `'code'` 键（`session_expired`/`session_limit`，additive 旧前端忽略、US-005 前端据此弹阻断弹窗）→ 显式 `ws.close()`，不发 manifest。容量闸门（429 session_limit）实际由 HTTP 层 `POST /api/session`（create=True）把关；WS/读路径 create=False 对未知 sid 一律 401 session_expired（`resolve` 的 not-create 检查先于容量检查）—— 帧**格式**对两 code 通用（白盒单测锁定）。
- **WS 快照口径不变量**：accept 阶段快照改自**会话**（带 sid = commit 注册的 per-doc 快照；缺省 = default = `_PIECES_STATE` 同 dict）。会话 state 从不原位 mutate（commit 整体 rebind `st.state`）→ 「整连接一次快照、中途不切数据」保持。
- **求解回调刷活性**：`on_manifest` / `on_report` 内 `session_registry.touch(sid)`（求解期间客户端不发消息也不被扫描误杀；单 float 写 GIL-safe 不加锁；会话已不在则 no-op）。
- **测试**：`tests/test_read_routes_sessions.py` 13 例（ptypes/band/prefix/export 双会话隔离 + 无 sid default 回归 / export 过期 401 JSON + 未注册 401 + 非法 400 四端点 / GET / no-cache / WS 合法 sid 全流程 manifest→frames→final + ws_open 钉住归零 / WS 无 sid default / WS 过期 error 帧 + close / WS 超限帧契约白盒 / WS 求解中扫描不逐出断开后可逐出）。

## 多会话 US-004 关键约定（策略长跑会话化；2026-08-27）

- **每会话一份策略状态**：`_STRATEGY_STATES[sid]`（`_states(sid, create=)` 单一取用点，读路径不建空槽）；default 会话 = 旧名 `_STRATEGY_STATE` **同一对象**（既有测试直改 `_STRATEGY_STATE` 零改动兼容，`_STRATEGY_STATES[DEFAULT_SID]` 由 `_states` 惰性回填同一引用）。会话过期/逐出**不清理**本表 —— 同 sid 回来（墓碑 1h 过龄后可重建）仍能经内存态（本进程未重启）或本 sid marker（重启后 orphan 路径）发现/清理自己的遗留 run。
- **会话闸门**（`_session_gate(sid)`，四路由共用）：非 default sid 走 `registry.resolve(sid)`（读路径 create=False —— 数据必已由 commit 注册）+ 顺手刷 `last_active`（**status 轮询即活性**，10-60 分钟长跑中的会话不被扫描线程逐出）；SessionError → `JSONResponse(e.payload(), e.status)` fail-fast 先于 409/422/一切校验。default 豁免（`_pieces_state()` 延迟取用保持既有测试打桩点）。
- **run 存活钉住 + 终态宽限窗（2026-08-30，`_run_alive_hook`）**：轮询中断（睡眠唤醒前/关页/跑完挂机）时「轮询即活性」失效的兜底 —— hook 决策表：非终态 + `proc.poll() is None` → 滚动短豁免 `clock()+_RUN_ALIVE_HOLD_SEC(90)`（须 > 2× 扫描周期 30s，防窗口 ≤ 周期时下一轮扫描恰越界把活 run 逐出）；非终态 + 进程死 → 幂等记 `st['proc_dead_ts']`（daemon 首次探测时刻，**锁内禁 IO**，终态固化留给正常轮询）→ `proc_dead_ts + RESULT_GRACE_SEC`；终态 → `terminal_ts + RESULT_GRACE_SEC`。`terminal_ts` 两处 set-once 落点（`_status_from_active` 终态固化 carry-over `proc_dead_ts` / `_stop_common` 树杀取 `or clock()`），轮询续读不刷新（否则宽限窗被无限续期）；start 的 `st.clear()` 自然抹掉两个时间戳（二跑不继承豁免）。时钟统一 `session_registry.clock()`（与 TTL 同源，FakeClock 可注入）。宽限窗外逐出照旧走墓碑 → 同 sid 回来仍能经 `_STRATEGY_STATES`/marker 发现清理遗留 run（既有语义不变）。

## US-033 关键约定（PLT 导出 调用方必读）

- **背景**：现有 DXF 导出在 WT「高速绘图 V8.8 网络版」+ LIKE 绘图仪上**实测无法正常打印**；该软件原生吃 PLT/HPGL（与 ET 排料软件同口径），故新增 PLT 导出链路。MVP 不做物理设备验收（现场由用户落地后反馈）。
- **`write_marker_plt(world_pieces, *, width_mm, gate_mm, title) -> bytes`**（`web/export.py`，签名与 `write_marker_dxf` 对齐；`title` 仅保签名，不输出）：
  - HPGL 常量：`_PLT_SCALE=40`（1mm=40 plotter unit ≈ 0.025mm）、`_PLT_PEN_WIDTH_MM=0.08`、`_PLT_PEN=1`（**全文件唯一笔号**，2026-08-24 用户要求统一颜色=门幅框蓝色，WT 预览按笔号着色、首版按层分 SP1-SP5 五笔预览呈多色已废弃；生产 PLT 实测同样全程仅 SP1 一笔、0 处 PC，勿回退多笔）；`_LAYER_OUTLINE/NET/INTERNAL/NOTCH/GRAIN` 为层收集桶（输出层序，不对应笔号）。
  - 指令序列（**封装口径对齐生产 PLT** `data/PC-20250508NJIF*.plt`）：`IN;PS<纸长>;SP1;PW0.08;` 头部一行（纸长 = max(用布长度, 内容最大X)×40，含刺口±4mm 延伸；无 PS 时 WT 按默认 A0/A3 页幅裁切 7m+ marker）→ **全程单笔 SP1**：门幅框（闭合 PU+PD 4 角）+ 逐片 5 层按层序平铺（轮廓→净版→内部线→刺口→布纹，无 SP 切换）→ `PU;` → `PG;`（出纸收尾）。**CRLF 行尾**；**无 VS/LB 指令**（生产文件均无）。
  - **越界防御** `_plt_frame_stats`：全层顶点 + notch 点须在门幅框内（容差 0.5mm），非 0 记 warning（曾因 notch 未随片旋转产生 600 越界点把 WT 预览拉变形，见 `nesting_bounds/load_pieces.py` 修复）；notch 沿法线 ±4mm 端点外伸门幅属工艺正常，只计入 PS 取值不告警。

  - **闭合策略**：`_plt_polyline(closed=True)` 在 PD 末尾追加首点（物理闭合，与 `write_marker_dxf` POLYLINE 首尾补点策略一致）；内部线/布纹线/刺口 `closed=False`。
  - **空层跳过**：`net_polygon`/`internal_lines`/`notches`/`grain_line` 空则该层无笔画（门幅框 + outline 恒出现）。
  - **布纹箭头线 + 尺码×数量标注（2026-08-24）**：布纹层升级为**单头箭头线**（指向原始画向 B 端：grain_line A→B 端点顺序全程保序 = 母版 layer7 画向；头部对称双羽各 30mm/15°，短杆按 45% 杆长收缩；首版双端形态经用户纠正改单头）+「尺码*数量」**矢量笔画标注**（生产 PLT 逆向：全程无 LB，文字即 PU/PD 笔画；沿画向 u=A→B 阅读、字顶朝 w=(-uy,ux)（画向**左**法线；(u,w) 必须右手系 det>0，否则字形映射整体镜像——首版 w=(uy,-ux) 左手系即"所有文字不分画向全反"bug，2026-08-24 用户截图纠正）、基线离杆 10mm、中心锚 0.85·L；正向(+X)片字顶朝上标注在杆视觉上方、180° 片随片倒置翻到杆视觉下方（用户口径：文字恒在箭头上方，反向片视觉在下是因为片自身倒了 180°）；数量 = 同 pid 副本数（demand>1 → world_pieces 同 pid N 行）；内置数字 0-9+'*' 单笔字库，字库外字符整段跳过 all-or-nothing；几何规则单一真相源 `_grain_annotation_strokes`）。
  - **坐标系**：spyrrow 世界坐标 X=用布长度 Y=门幅 Y 向上，与绘图仪走纸/幅宽天然一致；**绝不带前端 SVG `scale(1,-1)` 翻转**（docstring 显式约束）。
  - 纯标准库字符串拼接，`'\r\n'.join(cmds).encode('ascii')`；**无临时文件**（比 DXF 的 ezdxf 写盘读字节更简单）；**无新 pip 依赖**；全 ASCII，`.decode('ascii')` 不抛异常。
- **`server.py /export` 路由**：`elif fmt == 'plt':` 分支插在 `dxf` 之后、`else` 之前；title 复用 DXF 同款 ASCII（`M1787 util=<pct>% L=<L>cm gate=<gate> seed=<seed>`）；`media, ext = 'application/plt', 'plt'`；文件名拼接走现有 `ext` 变量自动命中（`排料_码<sizes>_<pct>pct_seed<seed>.plt`）。PNG/DXF 行为零回归；未知 fmt 仍返 400 `{error:'未知格式 <fmt>'}`。

## 多会话 US-006 关键约定（uploads 磁盘 TTL 清理；2026-08-27）

- **背景**：多会话放开后 `out/uploads/` 只进不出（每上传 ~3MB dxf + commit 建 110 裁片切片目录 + 策略 cfg），会话过期后无人引用也无人删。TTL 兜底让磁盘占用有界。
- **成对判龄（关键防误删）**：同一 doc 的 dxf 与 `_pieces` 目录**任一侧未超龄 → 整对保留** —— commit 重写 pieces 目录（mtime 刷新）但不动 dxf 的 mtime（上传时刻），按单侧独立判龄会误删「上传很久但刚 commit 过」的母版。孤儿单边（无对侧）按自身 mtime 独立判龄。
- **保护集三源**：① `registry.active_doc_ids()`（`st.doc_id` ∪ 快照 `state['doc']['doc_id']` —— 后者覆盖 default 会话启动 reload 形态，`SessionState.doc_id` 仅 commit 路由填写）；② `out/config_runs/.web_strategy_active*.json` 全部 marker 内 `doc_id`（glob 覆盖 default 旧名 + sid 分文件；**会话已过期但策略 run 仍在跑 → master 不误删**，注册表逐出不通知磁盘，marker 是该场景唯一保护来源）；③ mtime 未超龄。坏 marker / 读不到 mtime → 跳过或按未超龄处理（宁漏删不误删）。
- **触发点两处**：进程启动 = `server.main()` → `start_startup_cleaner()`（daemon 线程不阻塞启动；**不放模块级 import** —— TestClient 测试导入 app 会起线程扫真实 out/）；commit 成功后 = 路由尾 `await loop.run_in_executor(_executor, diskclean.trigger_cleanup, str(UPLOADS_DIR))`（executor 不阻塞事件循环；**显式传 `UPLOADS_DIR` 模块常量**：存量测试只 monkeypatch `server_mod.UPLOADS_DIR` 不 patch `paths.OUT_DIR`，不显式传会扫到真实 out/ 误删真文件）。
- **best-effort 双层兜底**：单条目删除失败（目录被占用等）在 `scan_uploads` 内 warn 跳过继续；扫描阶段意外异常由 `trigger_cleanup` 整体吞掉仅 warn —— 绝不向调用方抛，commit 响应不受影响。
- **只管理 web 自有命名**：`<SID_RE>.dxf` / `<SID_RE>_pieces` / `strategy_cfg_*.json` 三类；其余文件名（含 doc_id 不合法的 dxf）一律不动。
- **测试隔离**：单测全参数注入（目录/TTL/时钟/私有 `SessionRegistry`）；路由级测试 patch `server_mod.UPLOADS_DIR` + `paths.OUT_DIR/CONFIG_RUNS_DIR/INTERMEDIATE`，且**快照/恢复共享 `_PIECES_STATE`**（无 sid commit 会 reload 原位改写它，不恢复会污染 test_ws_stop 等依赖已加载状态的测试）。
