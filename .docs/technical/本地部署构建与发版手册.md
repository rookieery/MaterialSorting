## 1. 构建机一次性准备

| 组件 | 要求 | 说明 |
|------|------|------|
| 仓库 venv | `.venv`（python 3.11） | nuitka **4.3rc3**（验证基线；4.2.2 优化器对本闭包偶发 `mergeBranches` 内部 TypeError）+ **ordered-set**（缺它退纯 Python fallback 同样偶发崩）+ zstandard（可选） |

| node | 已装即可 | 前端 `cd materialSorting-web && npm run build` 产 `static/`（发版前跑一次；dist 检查会核对 index.html） |
| spyrrow 私有 wheel | `0.9.0+msN`（N≥1） | 构建期钉板校验不一致会 **exit 1**；切换见 [spyrrow私有wheel构建与升级手册](spyrrow私有wheel构建与升级手册.md) |
| Inno Setup 6 | **可选**（`--installer` 线） | `winget install --id JRSoftware.InnoSetup --scope user`（免管理员，落 `%LOCALAPPDATA%\Programs\Inno Setup 6`）或官网 <https://jrsoftware.org/isdl.php>。**简体中文语言包已随仓 vendor**（`scripts/installer/ChineseSimplified.isl`，源 = issrc 官方仓库 Unofficial 翻译，无需另装）。无 Inno 时 `--installer` 打印指引**跳过不失败**，绿色 zip 照常产出 |

**构建资源红线**（2026-09-27 整机假死事故复盘，详见 build_freeze.py 头注记）：

- 构建前**停 ms-web / 长跑 solver 等常驻 CPU 负载**；
- `--jobs` 上限 8（缺省 `min(8, max(2, 核数//4))` + 内存钳制每 job ≥3GB），**绝不裸跑全核**；
- 全量构建预算 30~90 分钟，期间系统应保持可交互（子进程 BELOW_NORMAL 优先级）。

## 2. 日常发版三步

```text
① tag        git tag v0.1.0 && git push origin v0.1.0        # 版本串 = pyproject + git describe
② 构建       .venv/Scripts/python.exe scripts/build_freeze.py --installer
③ 归档       dist/ 三件套拷贝到发版目录（网盘/U盘），归档记录 tag ↔ 产物哈希
```

**② 七步流水**（`--installer` 时 6+1；任一步失败 exit 1 并打印步骤名）：

| 步 | 内容 | 失败口径 |
|----|------|---------|
| 1/7 | 前端 static 存在性检查 + 样例母版预检（repo `data/` 顶层 `.dxf`） | static 缺 = 提示先 `npm run build`（`--skip-frontend-check` 可跳）；样例空 = exit 1（2026-09-29「exe 无可用样例」事故同型防复发） |
| 2/7 | 环境自检（nuitka 版本 / zstandard / ordered-set） | nuitka/ordered-set 缺 = exit 1（附 pip 命令） |
| 3/7 | spyrrow 私有 wheel 钉板校验（含 warm 预探测） | 不一致 / `+ms<N>` N<1 / warm 探测失败 = exit 1 |
| 4/7 | 孤儿编译进程扫描（硬重启残留 = 双倍风暴） | 命中 = exit 1（`--force` 放行） |
| 5/7 | Nuitka 编译（`--jobs` 显式、MinGW64、双元数据红线） | 退出码非 0 = exit 1 |
| 6/7 | dist 自检（源码泄漏 grep 零命中 + `exe --check` frozen/warm/version/static/fonts/data） | 任一不过 = exit 1 |
| 7/7 | 安装包 + 绿色 zip（`--installer`）：ISCC 编译 iss → `MaterialSorting-Setup-<版本>.exe`；zip → `MaterialSorting-portable-<版本>.zip` | ISCC 失败/产物未落 = exit 1；**ISCC 缺席 = 打印指引跳过不失败** |

- `<版本>` = 文件名安全串（如 `0.1.0-g590375b-dirty`），与 exe 属性页完整版本串（`0.1.0 g590375b dirty`）同源自 `pyproject + git describe`。
- **补打包**：iss 迭代 / 忘带 `--installer` 时，`build_freeze.py --installer-only` 对既有 dist 直接跑 6+7 步（不重编译；版本串取**当前** git 态，正式发版仍以全量 `--installer` 为准）。
- **signtool 钩子**（PRD 定案⑦不采购证书，路径预留）：env `MS_SIGNING_PFX` + `MS_SIGNING_TS`（+可选 `MS_SIGNING_PWD`）同时在场才对 setup.exe 调 signtool；配了 env 但 PATH 无 signtool = exit 1（不该静默出未签名包）。

**③ 归档产物**（`dist/` 已 gitignore，不入库）：

| 文件 | 说明 |
|------|------|
| `MaterialSorting.dist/` | onedir 本体（~230 MiB；含 exe 同级 `data/` 样例母版目录 —— 顶层 `.dxf` 逐文件捆绑，2026-09-29） |
| `MaterialSorting-Setup-<版本>.exe` | 中文安装包（LZMA2/max solid，实测 57 MiB） |
| `MaterialSorting-portable-<版本>.zip` | 绿色 zip（实测 87 MiB；单一顶层目录 `MaterialSorting/` + 一行启动说明.txt） |

## 4. 升级动线（v1 = 手动覆盖安装）

程序与用户数据**物理分离**：程序在安装目录（`%LOCALAPPDATA%\Programs\MaterialSorting` 或 zip 解压目录），用户数据恒在 `%LOCALAPPDATA%\MaterialSorting\out`（上传母版 / config_runs / run_stats.jsonl / 状态文件）——**两种升级形态均不触碰用户数据**。

| 形态 | 升级动作 |
|------|---------|
| 安装包 | 关闭程序（关控制台黑窗）→ 双击新 `Setup-<新版本>.exe` 覆盖安装（同 AppId 自动记住原目录；程序在跑会弹「检测到正在运行」提示关闭）。装完桌面/开始菜单图标原位刷新 |
| 绿色 zip | 关闭程序 → 解压 zip 用 `MaterialSorting/` **整体覆盖原解压目录** → 双击 MaterialSorting.exe |

**版本识别（售后定位用户在跑哪个版本）**：

1. exe 属性页：详细信息 →「文件版本」`0.1.0.319` /「说明」含完整串 `0.1.0 g590375b dirty`；
2. 命令行：`MaterialSorting.exe --check` → `version:` 行（无副作用，不起服务不开浏览器）；
3. 交付物文件名：`Setup-<版本>.exe` / `portable-<版本>.zip`；
4. 控制面板 → 应用 → MaterialSorting（牛仔裤排料）→ 版本列。

## 7. keyserver frp 部署 runbook（key 授权系统，US-009 2026-09-28）

key 授权体系 = **keyserver**（发卡/绑定/记账权威，独立顶层系统 `keyserver/`，`ms-keyserver` / `python -m keyserver.app`）+ **MS 排料工作台消费端**（冻结 exe 内 keygate）。现场形态：keyserver 与 frpc 部署在**同一台现场机**（可联网的普通 Windows/Linux 机），公网侧经 frp 隧道暴露给发卡方（管理后台 + admin API）与各客户机（消费 API）。完整 HTTP 契约（四 MS 端点字段表 / 错误码矩阵 / 三入口双闸时序 / keyserver 九接口摘要）见 [agent-api-reference.md](agent-api-reference.md) 的「key 授权体系契约专节」。

### 7.1 keyserver 启动

```bat
:: Windows 现场机（cmd）
set MS_KEY_ADMIN_TOKEN=<发卡方管理口令>
set MS_KEY_CLIENT_TOKEN=<消费口令>
set MS_KEY_DB=D:\keyserver\data\keys.db
ms-keyserver            :: 或 python -m keyserver.app；缺省 127.0.0.1:8110
```

env：`MS_KEY_PORT`（缺省 8110）/ `MS_KEY_HOST`（缺省 127.0.0.1 —— **只绑回环**，公网侧全走 frp，不裸露 LAN）/ `MS_KEY_DB`（缺省 `<keyserver 部署目录>/data/keys.db`）/ `MS_KEY_DEV=1`（**仅本地调试**：两 token 均未配置时放行；生产严禁设）。

### 7.2 frpc 配置样例（同机部署）

```toml
# frpc.toml（keyserver 与 frpc 同机；打 127.0.0.1 走本机回环）
serverAddr = "frps.example.com"          # 发卡方 frps 公网地址
serverPort = 7000

[[proxies]]
name = "keyserver"
type = "tcp"
remotePort = 18110                        # frps 侧对外端口
[proxies.transport]
useEncryption = true                      # frp 隧道层加密（与应用层 TLS 二期互补）
```

公网入口即 `http://frps.example.com:18110`：发卡方浏览器开 `/admin`（管理后台，token 在登录框输入）、admin API 走 `/api/admin/*`；各客户机 MS 的 keyserver URL 填同一地址。

### 7.3 双 token 必设（MS_KEY_ADMIN_TOKEN + MS_KEY_CLIENT_TOKEN）

**生产部署两个 token 必须同时设置**，缺任一 = 对应端点族整体 403（设计如此，fail-closed）：

| token | 护的资产 | 请求头 |
|-------|---------|--------|
| `MS_KEY_ADMIN_TOKEN` | 管理端五接口（建 key/续期/删除 = 财务操作）+ 管理后台数据面 | `X-Admin-Token` |
| `MS_KEY_CLIENT_TOKEN` | 消费端四接口（bind/merge/info/**validate 扣次**） | `X-Client-Token` |

**MS 消费端怎么带上 client token**（US-009 起支持，keygate 自动附头）：客户机设 env `MS_KEY_CLIENT_TOKEN` 或 exe 旁置 `key_client_token.txt`（见 §7.4）—— token 值随发卡交付物（sidecar 文件）下发全部客户机，是**共享秘密**（防公网任意调用方，不是逐客户身份）；漏配现象 = keyserver 401「消费 token 缺失/错误」中文透传到工作台弹窗。

**为什么不能靠 loopback 兜底**：常见部署会把「来源是 127.0.0.1 视为可信内网调用」当免 token 兜底；但 frp 同机部署形态下，**公网流量经 frpc 转发后来源 IP 恒为 127.0.0.1** —— loopback 放行等于公网裸奔（任何人拿到 frp 入口即免 token 建 key/扣次）。因此 keyserver 鉴权**明确不做 loopback 放行**（2026-09-28 决策台账）；token 未配置且无 `MS_KEY_DEV=1` → 端点族 403。token 校验用 `secrets.compare_digest` 常量时间比较（防时序侧信道逐字节猜）。

### 7.4 MS 消费端接线（客户机）

keyserver URL 三档解析链（`keygate.resolve_key_server_url`）：① env `MS_KEY_SERVER_URL` → ② **sidecar `key_server_url.txt`（frozen = exe 旁优先 → `%LOCALAPPDATA%\MaterialSorting\out\license\` 回落 —— 2026-09-29 回落档：license/ 是 key 授权机器本地权威目录（key_state.json 本就落此），新构建 dist 不带 sidecar / 安装目录只读 / 覆盖重装场景接线不丢（当日实发：新冻 dist 未放 sidecar，exe 弹窗「授权服务器未配置」而同机源码部署正常）；dev/源码部署 = `<OUT_DIR>/license/` 即 out/license/，gitignored 机器本地 —— 2026-09-29 加档：源码部署下后端被裸起/换启动方式重启会丢 env 级接线，落文件后任何启动方式自动带上）**，UTF-8 一行 URL → ③ 皆无 fail-closed（三入口运行一律拒绝）。

**client token 解析链同构**（`keygate.resolve_client_token`，US-009）：① env `MS_KEY_CLIENT_TOKEN` → ② **sidecar `key_client_token.txt`（位置同上按形态 —— frozen 双位置同序 exe 旁优先 → license/ 回落；frozen 形态随 key_server_url.txt 一并交付客户）** → ③ 皆无则请求不带 `X-Client-Token`（keyserver 未设 token 时不影响；**已设而本机未配 → 消费请求 401 中文透传**，绑定/校验全被拒 —— 客户机漏配 token 的现象即「消费 token 缺失/错误」）。

```bat
:: 首选：安装目录（exe 同级）新建两个 sidecar 文件（发卡交付物随包放置）：
key_server_url.txt       → http://frps.example.com:18110
key_client_token.txt     → <与 keyserver 侧 MS_KEY_CLIENT_TOKEN 同值>

:: 等效回落位（exe 旁不可写/覆盖重装时）：两文件放 license 目录
::   %LOCALAPPDATA%\MaterialSorting\out\license\（与 key_state.json 同目录）
```

自检：`MaterialSorting.exe --check` → `key_server_url:` 行回显 URL + 来源标注（US-009 起；2026-09-29 起来源区分 exe 旁 / license/ 回落档，售后可定位实际命中文件）；`key_client_token:` 行回显配置态 + 来源（**值不回显**）；`machine_guid:` 行回显注册表 MachineGuid 读取结果；`key_state:` 行回显 `key_state.json` 落点与绑定态。

### 7.5 HTTP 明文残余风险备案（2026-09-28，TLS 二期）

frp 隧道层 `useEncryption` 覆盖**现场机 ↔ frps** 段，但 **frps ↔ 客户机/发卡方浏览器段是明文 HTTP**：链路嗅探可见 key 明文（`MS-XXXXX-XXXXX-XXXXX`）与 token。残余风险评估：key 绑定 MachineGuid 后**他机不可用**（bind 即绑死，偷到的 key 在别的机器 validate 403「未绑定当前系统」）；token 泄露才是实质风险（可建 key/扣次），发现异常立即改 env 重启 + 换 token。**TLS（https 反代或 keyserver 原生 TLS）为二期立项**，一期备案接受该残余。

### 7.6 SQLite 定期快照备份

keyserver 全部状态在单文件 `keys.db`（SQLite，WAL 模式由连接参数控制；`data/` 目录下可能伴生 `-wal`/`-shm`）。**备份口径 = 冷拷贝整目录**（含 -wal/-shm，避免热拷贝单文件丢 WAL 页）：

```bat
:: 例：每日任务计划冷备（keyserver 停启窗口内执行最稳；热备至少带上 -wal/-shm）
robocopy D:\keyserver\data \nas\keyserver-backup\%DATE:/=-% /E
```

恢复 = 整目录回拷 + 重启 keyserver（`/api/key/health` 探活确认）。op_log/daily_usage 全在库内，回拷即完整恢复（发卡审计 + 使用统计不丢）。
