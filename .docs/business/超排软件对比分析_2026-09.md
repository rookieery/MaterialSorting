# MaterialSorting 对比业界超排软件 · 功能对比分析

- **日期**：2026-09-16（竞品资料为当日公开网络检索快照）
- **背景**：项目定位「牛仔裤排料引擎 + 可视化工作台」，核心目标 M1787 直筒 8 码套排 90%+ 利用率。为创始伙伴讨论与后续路线取舍，将本项目功能面与业界主流超排软件逐维度对比，给出优势/劣势与差距优先级。
- **证据基础与口径声明**：
  - 本项目功能面来自全库实读盘点（README / `.docs/` 全部业务文档 / 前端 `materialSorting-web/src/` 页面组件 / `web/` 路由清单），非自述；
  - 竞品信息来自公开资料（官网/帮助文档/发布会/教程，见文末来源），**各厂商利用率数字均为营销口径**，与本项目 `real_density = 原面积/(料长×幅宽)` 的版师口径不可直接换算比较；
  - 本文引用的本项目实测数据（91.71%、+2.27pt、−0.597pt 等）均为自测同一口径，出处见对应验收报告。

## 三、本项目相对优势

### 1. 利用率上限与算法现代化 —— 核心卖点

jagua-rs/sparrow 是近年开源界最活跃的异形件排料求解器（Rust 原生、条带 + 碰撞四叉树），算法代次高于 ET/富怡 2000 年代的自研内核。实测：5336 实例 4h 极限运行 **91.71% 破 90% 生死线**（[极限运行_AB验收报告.md](极限运行_AB验收报告.md)），且 race→extreme 同预算再 +0.4pt。对比参照：AccuNest 多核版的卖点只是"比自家标准自动排料再省 2%"，而本项目把"同预算下怎么多挤"做成了完整的可复现工程。

### 2. 「预算-利用率」策略工程化 —— 业界独一份

商业超排的时间控制只有一个参数"排 N 分钟"。本项目有：race 门杀（90s 门严格破 bar 才续跑、省出预算再投资、首 seed 豁免）、SE 篮延（冠军零方差延长求值）、极限运行（best-of-k 右尾最优）、kill 引擎（标定包络 + shadow 模式 + 假阳性统计）、θ₀ 按实例类历史校准（PC-009 run_stats.jsonl）、ETT 离线仿真器。这是把"求解预算当资源调度"做成了学科，ET/富怡/格柏均无对等物。

### 3. 工艺构造深度：成带/成套是构造性几何解，不是启发式

- **腰头成带 v2/v3**（[腰头成带_落地方案.md](腰头成带_落地方案.md)）：单副本异码链滑移贴靠（实测缝隙 **0.00mm**）、弧片手性自适应、横向弯腰头 T-转置分支，端到端 A/B **+2.27pt**；
- **起始端成套前后幅**（[起始端成套前后幅_版师确认清单.md](起始端成套前后幅_版师确认清单.md)）：paired 同型 180° 互锁 + 近满幅异码补片（FR-3 弧线相切嵌入）、无 RNG 跨进程确定性重放、钉位/驱逐重插。

通用软件的"捆绑排料/锁片/组合件"是人为把几片拴一起交给引擎碰运气；本项目是把版师的构造法**直接编译成确定性算法**，形态可控可验收。在牛仔裤细分这是实打实的差异化壁垒。

### 4. 交付正确性与验收文化

逐帧可行性白名单过滤（2026-09-16 根治"高级运行交付完全重叠布局"事故，见 git 6cfb0f7）、物理毛版口径全端统一（编辑画布红字 = PLT 实况）、同 seed 确定性重放 + 背靠背 A/B 验收报告制度、`num_workers=1` 逐帧全等的确定性边界备案。商业软件的输出质量是黑盒，本项目的每一分利用率提升都有可追溯证据链。

### 5. 工作台体验现代化

浏览器零安装、WS 实时帧流（利用率爬升可见）+ 求解过程回放、编辑弹窗拖/转/镜像/吸附/智能微调（去旋转 + 去重叠 + 压缩回收，纯函数确定性）、多会话 6 并发隔离、会话过期 checkpoint 自动恢复、.msn 状态文件跨机传递。ET/富怡是单机单用户桌面软件；格柏/力克的企业版协作在云端但重且贵。

### 6. 开放性与可集成性

全量 HTTP/WS API、CLI 10 键 JSON 配置（headless 批跑）、开放格式 .msn、run_stats.jsonl 统计库。ET/富怡完全封闭无 API —— 这为后续 SaaS 化、对接 ERP/MES 留了全部门。国内同类里几乎只有本项目把"排料引擎"当可编程资产而不是桌面工具在做。

### 7. 与存量生产链路无缝衔接

DXF R12+POLYLINE 导出经 ET2008 实测互认（车间既有打版工具不动）、g 码可回写母版给版师对码（`scripts/embed_piece_codes.py`）、PLT 封装口径对齐 WT V8.8 / LIKE 绘图仪实测怪癖（PS 纸长 / PD 分块 / 走纸引导）、毛版变体 + 单线矢量汉字唛架 14 字段表格按生产参考件定版。落地是贴着真实车间设备打的，不是实验室产物。

### 8. 成本与自主可控

零 license、代码数据全自有，可按自己版师的规则继续进化（对条对格等按需补）；商业套件改规则要等厂商。

## 四、本项目相对劣势

### A. 功能覆盖面（最大差距，多为空白而非落后）

1. **无打版/放码** —— 定位使然（与打板模块解耦），但意味着永远依附 ET2008 等上游出母版；
2. **对条对格全库无实现** —— 牛仔裤素色斜纹影响小，但拓展衬衫/夹克/印花品类即卡壳（ET/富怡/Optitex 全有）；
3. **避色差/避段差/避边差/避瑕疵**（拉布换卷接头 splice 规划）—— 无，成衣量产刚需；
4. **高低层/多层数排料**（ET 睿排招牌功能）—— 无层数概念，单唛架口径；
5. **分床/裁剪计划** —— 哪些码合排、开几床、每床拉几层全靠人脑，床次只是 PLT 表格手输字段；格柏 AccuPlan / ET 自动分床是同价位位竞品标配，**这是对生产端影响最大的缺口**；
6. **多面料/面料库/缩水补偿计算** —— 门幅是单一数字，无面料档案；经纬缩水只是表格展示字段不做尺寸补偿（Optitex wizard 一次配置批量含缩水）；
7. **裁床 CUT 格式** —— 仅 PLT/DXF/PNG，上自动裁床（力克/格柏/富怡 CUT）需要另做格式层。

### B. 规模与部署成熟度

- 单机单实例架构（服务器 106 多实例互删产物事故在案）、全部路由**无鉴权**经 frp 隧道裸奔（[项目优化点盘点_2026-09.md](../technical/项目优化点盘点_2026-09.md) G1 已立案）、零 CI/lint；
- 并发容量是工作台级（6 会话），无分布式/云并行 —— Quick Nest 卖点就是云端无限并发唛架，AccuNest 有多核服务器，本项目极限运行也只吃本机 4 worker。

### C. 生态与兼容面

- **导入仅 DXF R12 POLYLINE+LINE**，LWPOLYLINE/SPLINE 母版不直接吃；竞品通吃各家 CAD 格式 + HPGL 读入 + 读图仪纸样数字化（AccuNest 明确支持从多数服装 CAD 导入）；
- 无读图仪/纸样输入入口，无培训/服务网络 —— ET 有成套教材课程（当当在售）、B 站教程生态，版师群体默认会 ET；本项目要版师改变工作习惯，迁移成本真实存在。

### D. 产品化打磨度

- solver 高级旋钮只进 CLI 不进 UI（对工程师友好、对车间排料师不友好）；
- 求解配置面极简（尺码/门幅/时长/band/prefix），缺少富怡那种"设完面料参数一键走"的傻瓜化向导 —— 极简是设计选择但也是上手门槛的另一面；
- 验证深度：5336 已破线，但 **M1787 主线 85.59% 距 90% 还差 ~4.4pt**，广度（更多款式/品类）未证；
- 确定性边界（num_workers=4 并行 merge 帧漂移）等工程细节需要专业理解才能运维。

## 五、综合定位与差距优先级建议

**一句话定位**：在"**同一张唛架排得更省、预算可控、结果可验收**"这个单点上，本项目（算法代次 + 策略工程 + 构造性工艺 + 现代工作台）已达到或超过 ET 超排 / 富怡 / 格柏的自动排料能力，牛仔裤细分的成带/成套构造甚至是独有优势；但在"**工厂全流程覆盖**"（打版→分床→拉布→多面料→裁床→ERP）上只占其中一环 —— 竞品是全家桶，本项目是尖刀。

**视野边界注记**：若把视野扩到其它场景的超排（钣金 SigmaNEST/ProNest、皮革/复合材料），那是不同约束类问题（自由旋转、共边切割、桥接微连接），本项目布纹硬约束 + 腐蚀压线的服装特化架构并不通用 —— 这是垂直深耕的代价，不是缺陷。

**差距优先级建议**（按生产端影响排序）：

| # | 差距项 | 理由与底子 |
|---|---|---|
| 1 | **分床/裁剪计划** | 最大刚需缺口；run_stats 历史库 + class_key 已是现成数据底座，天然适合做 |
| 2 | **多面料 + 缩水补偿计算** | 把 PLT 表格字段升级为真补偿，向导化 |
| 3 | **后台排队批量** | CLI 底子已全（ms-run-config headless），补队列调度 UI 即可对标"排队超排/过夜 AccuNest" |
| 4 | **部署安全与多实例** | 鉴权、产物隔离 —— 上多客户前必须解决 |
| 5 | 对条对格 / 裁床 CUT 格式 | 拓展品类、上自动裁床时再做 |
