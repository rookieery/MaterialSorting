# 裁片编号化（去名称化）重构方案

> 状态：**v5 终版**（2026-08-18；全部决策已落定：镜像全删 + internal 一并移除，母版维持现状；实施前经 PRD 最终确认）
> 前置：裁片标识 g 码体系已落地（`labeling.py` 单一真相源，见 排料规则_详细版.md §1.1）。
> 本方案是它的延伸：**g 码从「显示标识」升级为「全链路主键」**，程序中一切用裁片种类名称（前片/后片/腰/…）做匹配、键控、显示的逻辑全部换成 g 码。

## 1. 背景与目标

### 1.1 为什么要去名称化

1. **名称表不全面**：`GROUP_NAMES`（g00..g09 → 中文名）是人工确认的固定对照表，后续款式遇到未录入的名称将无法处理（现状：无映射的组在 commit 时**直接 skip 丢片**；实测最新母版 block 名几乎全是空格/数字，名称启发式已名存实亡）。
2. **解析名称会出错**：block 名 → 中文名的判定偶尔误判。现状下游 4 类**行为**拿中文名做集合/字典判断（镜像展开、内片腐蚀档、per_type 覆盖、颜色），名称一错行为就错。

### 1.2 已确认决策

| # | 决策 |
|---|---|
| D1 | 行为语义去名称化：不再有任何名称集合判断；未映射组不再丢片 |
| D2 | 高级配置：固定 10 中文列 → **当前母版实际 g 码动态列**，d/tol 键 **(label, sizeKey) 逐码** |
| D3 | PNG/SVG 图例条目改 **g 码**（每码独立编号，图例可能 10–20 条），颜色随 g 码 |
| D4 | 单裁片文件名改 **label 命名** + manifest 驱动加载 |
| D5 | 母版 block 原名（`name`）在 tooltip / 放大预览中也隐藏，一律显示 g 码 |
| T1 | **`GROUP_NAMES` / `PAIR_TYPES` / `INTERNAL_TYPES` / `ALL_TYPES` 常量在程序中彻底删除**（文档保留作历史口径） |
| T3′ | **镜像/paired 概念与功能全链路删除**（见 §3.2）：排料引擎 = 「母版几何 × 用户数量」，不合成、不锁左右、无任何镜像参数。生产口径已确认：实际排料文件本就单侧，**母版维持现状、无需重出** |
| R1 | **internal（内片）概念一并从产品面移除**：WS/UI 无任何 internal 字段；实验 CLI 保留 `--internal g04,g07` 参数（2026-08-18 确认） |
| T4 | 顺序赋码排序键前置 `group_key`（block 名派生，名称无关）保证跨码同号 |
| T5 | `dxf_parser/explore.py` 阶段 1 离线分析工具不动 |
| T6/T7 | 不做旧数据双读：旧 intermediate/旧切片目录明确报错「请重新 commit」 |

### 1.3 总原则

- **g 码 = 裁片唯一标识**：全链路（parse → commit → intermediate → WS → 前端 → 导出）主键化，键统一 `(label, sizeKey)`。
- **解析管种类（几何盘点），排料管数量（每种几份）**：母版里有什么轮廓就排什么轮廓，程序不无中生有（不合成镜像）、不丢片、不改名。
- **中文名在运行链路中清零**：不上屏、不键控、不落 intermediate（explore.py 离线工具除外）。

## 2. 目标数据模型

### 2.1 NestPiece（nesting_bounds/load_pieces.py）

```python
@dataclass
class NestPiece:
    pid: str          # f'{label}_{size}'，如 'g03_28'（无 _L/_R/_M 后缀 —— 镜像概念已删除）
    label: str        # g 码（主标识）
    size: int         # 码号
    polygon / bbox / area_mm2 / source / 5层字段   # 不变
    # ❌ 删除 ptype、side；无 paired / internal
```

### 2.2 intermediate（pieces_intermediate.json，schema v2）

```jsonc
// pieces[i]：每个母版轮廓恰一条（WYSIWYG：母版 N 个轮廓 → N 条）
{
  "pid": "g03_28",
  "label": "g03",
  "size": 28,
  "polygon": [...], "area_mm2": ...,
  "net_polygon": [...], "internal_lines": [...], "notches": [...], "grain_line": [...]
  // ❌ 删除 ptype / side / paired / internal
}
// 顶层 ptype_representatives → label_representatives（键 g 码，供 /api/ptypes）
```

### 2.3 parse-dxf 响应（/api/parse-dxf）

```jsonc
// sizes[i].pieces[j]
{ "label": "g03", "polygon": [...], ...5层 }
// ❌ 删除 name、ptype、paired —— 母版里有几个轮廓就返回几片，各配 g 码
```

### 2.4 /api/ptypes 响应

```jsonc
{ "representatives": { "g03": { "polygon": [...], ...5层 } } }   // 键 ptype → label
```

### 2.5 WS 线格式（/ws/solve）

```jsonc
// start：只有数量与逐片覆盖，无任何片型语义
{
  "quantities": { "g03": { "28": 2 } },                      // 份数 demand：每个 g 码每码独立配，天然支持任意不对等组合
  "per_type":   { "g03": { "28": { "d": 1.5, "tol": 2 } } }   // D2：label × sizeKey 逐码
}
// manifest.pieces[i]：{ "id": "g03_28", "label": "g03", "size": 28, "color": ..., "demand": 2, ...5层 }
// ❌ manifest piece 删 ptype；id 无 side 后缀
```

### 2.6 /export 请求（POST /export）

无需任何额外配置：placed 的 pid（`g03_28`）在 intermediate 里**直接可查**，导出零重放。

### 2.7 上传切片目录（uploads/<doc_id>_pieces/）

```
g03_28.dxf            # 文件名 = {label}_{size}.dxf（每码内码唯一 → 天然无重名）
g03_30.dxf
pieces_manifest.json  # 新增 sidecar（加载驱动源）：[ { "file": "g03_28.dxf", "label": "g03", "size": 28 }, ... ]
```

`load_nest_pieces` 改为 **manifest 驱动**：每文件布纹对齐 + 归一化，**无镜像展开分支**。文件名仅人读，语义全在 manifest。

## 3. 关键链路

### 3.1 commit 管线重排

现状（名称是枢纽、commit 期合成镜像）：

```
collect → assign_group_no → GROUP_NAMES 定 ptype（无映射→skip 丢片）
  → write_piece_dxf({中文名}_{size}.dxf)
  → load_nest_pieces（ALL_TYPES 文件名扫描 + PAIR_TYPES 镜像展开 L/R）
  → compute_size_ptype_labels（(size,ptype)→label）→ intermediate
```

目标（label 先行、名称清零、零合成）：

```
collect
  → assign_codes(pieces)                     # g 码最先算；签名去掉 gmap/group_names
  → write_piece_dxf({label}_{size}.dxf) + pieces_manifest.json
  → load_nest_pieces(manifest 驱动，对齐 + 归一化，不展开)
  → intermediate（每母版轮廓一条）
```

**AC#5 对齐不变量简化**：parse 与 commit 各自对同一母版跑 `assign_codes`（同 collect、同排序键、同母版码规则）→ 同一 `(block_name, size, piece_index)` 必得同码；不再经过 (size, ptype) 中转。

### 3.2 镜像删除的依据与口径（T3′ 核心）

**移除依据（三层）**：

1. **算法层**：sparrow 只见多边形，手性对求解器无语义——镜像合成从来不是排料引擎的职责。
2. **表达力层**：`paired` 布尔把成对片锁死为「L 数 ≡ R 数」，反而表达不了不对等排料；数量矩阵（每个 g 码 × 每码独立份数）天然表达一切组合。
3. **生产实证（用户确认）**：实际生产中排料文件本就不含左+右镜像几何——镜像不是排料环节的事实需求，母版维持单侧现状即可。

**移除后的口径**：

- 母版出什么轮廓，排料图就有什么轮廓；每片排几份由数量矩阵说了算（WYSIWYG，零合成、零丢片）。
- 成对/左右语义完全离开系统：留给母版（画几块是几块）+ 数量（各配几份）+ 裁剪端（怎么裁）。程序不再有任何 paired 参数、镜像分支、L/R 后缀、齐套校验。

| 场景 | 旧模型（paired 布尔） | v4（数量即一切） |
|---|---|---|
| 常规（某片 N 份） | paired ✓（程序合成镜像，L=R=N 锁死） | ✓ 该 g 码配 N |
| **不对等组合（3 份 vs 2 份）** | ✗ 表达不了 | ✓ 各自独立配数 |
| 未录入名称的片 | ✗ 丢片或靠猜 | ✓ 有轮廓就排 |

**连带删除**：constraints 的成对齐套校验（服务于已删除的合成模型）；intermediate 物理片数对当前母版从 176 → 110（每母版轮廓一条），历史基线按新口径重建（§9 P4）。

## 5. 颜色与图例方案（D3）

- **调色板单一真相源**：`sparrow_baseline.py` 共享层新增 `LABEL_COLORS`（16 色循环表，延续 d3 系），`label_color(label) = PALETTE[(code-1) % 16]`。solver / export / SVG 复用；前端颜色仍由 manifest `color` 下发。
- **同码同色**：g03 在 28/30 码同色（码号由叠印文本区分：PNG `g03`、DXF TEXT `g03-28`）。
- **图例条目** = 本次排料出现过的 label 并集（当前母版约 10 条/码并集后 ≤20），按 g 码数值序；图例标题「片型」→「裁片」。
- **DXF ACI**：`((code-1) % 24) + 1`。

## 6. 高级配置弹窗（D2）

结构与数量矩阵同构（复用 QtyMatrix 交互范式与样式），**只管 d/tol**：

```
┌ 高级配置：逐裁片覆盖 ──────────────────────────────┐
│         g01     g02     g03     …（列=当前母版 g 码并集） │
│  28  [d|tol] [d|tol] [d|tol]                          │
│  30  [d|tol] [d|tol] [d|tol]    ← 每格两个小输入       │
│  …（行=参与排料的码号）                                 │
│  列头：缩略图 + g 码徽章 + ≡ 整列设值                    │
│  空 = 继承全局默认（0/0）；行/列支持整行整列设值           │
└──────────────────────────────────────────────────────┘
```

- 列集合来自 parse 响应 label 并集，按 `compareByLabel` 数值序；缩略图 `/api/ptypes`（label 键）。
- 草稿 + 确定、ESC/遮罩、双层 modal 独立 ESC 等既有约定保留。
- `collectParams` 输出 `{label: {sizeKey: {d?, tol?}}}`（空串剔除；整体空 → null）；后端 `per_type[label][sizeKey]` 命中即覆盖，label 缺席（旧 intermediate）忽略。

## 10. 验收总标准（用户视角）

1. 上传**任何**母版（含未录入名称、无名 block 的新款）→ 全部轮廓有 g 码、不丢片、不合成、可排料。
2. **数量即一切**：每个 g 码 × 每码独立配数，任意不对等组合可表达；排料图 = 母版轮廓 × 数量（WYSIWYG）。
3. 界面（tooltip/弹窗/矩阵/预览）与导出（PNG 图例/SVG/DXF TEXT）**零中文片型名**。
4. 高级配置按 (g 码, 码号) 逐片配置 d/tol，端到端生效。
5. 新基线（当前母版重 commit，110 片）同 seed 密度对拍一致；利用率不因去名称化/去镜像化下降。
