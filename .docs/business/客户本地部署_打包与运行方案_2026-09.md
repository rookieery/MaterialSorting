## 〇、结论先行

| 需求 | 可行性 | 一句话结论 |
|---|---|---|
| 1. 源码保护 | **可行，推荐 Nuitka** | Python 真编译为机器码（非字节码打包），交付物与 C++ 商软同级；算法核 spyrrow 本来就是 Rust 二进制，双层受益 |
| 2. 一步运行 | **可行，改动面极小** | 新增 launcher 入口 + 两处子进程 spawn 适配，即「双击图标 → 浏览器自动打开」；代码现状对冻结打包异常友好（全环境变量化路径 + 顶层 multiprocessing target） |
| 3. key 授权 | 方向可行 | 服务器 Ed25519 签发 / 客户端离线验签 + 本地配额计数，植入求解入口闸；细节另开 PRD，不阻塞 1/2 |

**总工作量评估：3.5~5 人日**（含构建流水线调通与干净环境验收，不含杀软误报的售后处理与代码签名证书采购流程）。

**与现有运维格局的关系**：本地部署顺带消灭三类服务器侧顽疾 —— 单机 CPU 瓶颈（求解吃客户自己的 CPU）、106 多实例策略互杀、frp 隧道暴露面；客户母版数据不出厂（对服装厂是卖点而非妥协）。

## 二、需求 1：源码保护

### 2.1 先定义威胁模型

「不能让客户知道源码」要拆成两档：

- **T1（主战场）**：客户/版师拿到安装目录，翻文件找 `.py`、用解包工具还原可读源码 → **必须挡住**。
- **T2（上限）**：专业逆向工程师对机器码做汇编级分析还原算法逻辑 → 任何客户端技术（含 C++ 商软、加壳）都只能提高成本、不能根除。本方案目标 = 把 T2 成本抬到远超目标群体（服装厂及同行软件商）的动机，配合合同保密条款兜底。

### 2.2 技术选项对比

| 方案 | 交付物本质 | 抗 T1 | 抗 T2 | 成本 | 判定 |
|---|---|---|---|---|---|
| **PyInstaller 裸打** | 自解压 + `.pyc` 字节码 | ✗（pyinstxtractor + 反编译器可完整还原） | ✗ | 免费 | **排除**——等于源码明文交付 |
| **PyInstaller + PyArmor** | AES 加密字节码 + 原生运行时解密 | 良好 | 中 | PyArmor 商业授权（按年） | **Plan B**——若 Nuitka 遇不可解依赖坑时回退 |
| **Nuitka（standalone/onedir）** | Python → C → 机器码（MSVC 编译） | 强（无字节码，只有 `.pyd`/exe） | 强（汇编级 RE） | 免费开源；构建慢（本项目估 10~20min）；构建机需装 MSVC Build Tools（一次性） | **✅ 定案推荐** |
| Cython 手工编译各模块 | `.pyd` 机器码 | 强 | 强 | 自制 Nuitka，构建系统维护成本最高 | 排除 |

选 Nuitka 的附加理由：

1. 本项目依赖（numpy/shapely/matplotlib/pydantic）均有成熟 Nuitka 插件或社区 hook 路径；
2. 国产杀软（360/火绒，工厂机常见）对 Nuitka 产物的误报率显著低于 PyInstaller（后者是恶意软件常用载体，特征面大）；
3. 开源无授权费，发版流水线无额外合规负担。

### 2.3 各资产的保护口径

| 资产 | 形态 | 口径 |
|---|---|---|
| 后端 Python 源码（nesting_engine 构造性算法、PLT 文字引擎、业务规则实现） | Nuitka 编译为机器码 `.pyd` | **不含任何 `.py`/`.pyc`**（验收项：dist 目录 grep 零命中） |
| 求解器算法核 spyrrow | 本来就是 Rust 编译的 `.pyd` | 天然保护，零额外工作 |
| 前端 React 源码 `src/` | 不进包；进包的只有 Vite minified `static/` | UI 壳，IP 密度低，minify 后可读性已差；如需加固可开 terser 混淆（v1 不必） |
| 业务规则文档 `.docs/`、`tests/`、`scripts/`、`prompt.md`/`progress.txt` 等 | **不进包**（Nuitka 只打 import 闭包 + 显式 data files） | 构建清单红线：显式排除，验收抽查 |
| 字体/单线字库数据 | 数据文件随包 | 无保密诉求（OFL 许可本身要求随包分发许可文件，`*.md` 已在 package-data） |

### 2.4 诚实的安全边界（写给决策者）

- 客户端交付没有「绝对防逆向」；Nuitka 后的强度 ≈ 传统 C++ 商用软件 —— 这在排料/CAD 行业已是标配水位。
- 真正的核心竞争力（sparrow 求解器 + 构造性成带/前缀算法 + 调参 know-how）分散在 Rust 二进制、编译后 Python、以及**不在包里的**标定数据与文档中，被一次性整体复刻的概率低。
- 需求 3 的 key 授权是第二层（限制「拿到了包的人」的可用性/时限），与需求 1 正交叠加。

## 三、需求 2：一步运行

### 3.1 交付物与用户动线（目标形态）

```
交付物：MaterialSorting-Setup-<版本>.exe（Inno Setup，中文向导，~150MB）
客户动线（全流程两步）：
  安装（一次）→ 桌面出现「牛仔裤排料」图标
  双击图标     → 黑色控制台窗口出现（服务日志）→ 默认浏览器自动打开 http://127.0.0.1:<port>
  使用         → 与现有工作台完全一致的 UI（上传/求解/导出）
  退出         → 关闭控制台窗口 = 服务停止（语义清晰）
```

- 分发形态：**安装包优先**（Inno Setup：桌面快捷方式、卸载器、中文 UI、per-user 安装免 UAC）；绿色 zip 为备选（解压即用，适合受限机器）。
- 客户机要求：Windows x64 / 无需 Python / 无需 admin / 磁盘 ~500MB / 内存 8GB+。
- **CPU 是求解时长的决定变量**（见 §6 风险 R3）—— 交付话术必须写明配置基线（建议 4 核 8G 起步、8 核 16G 推荐）。
- 可选升级（v2）：pywebview 原生窗口壳替代控制台+浏览器（更像桌面软件、无地址栏）；v1 用控制台方案 —— 简单可靠，且黑窗日志对现场排障是优点。

### 3.2 launcher 入口设计（新增文件，约 100~150 行）

新模块 `materialsorting/launcher.py`（Nuitka 编译目标，同时保留 `python -m` 可跑用于开发调试）：

```python
# 伪代码 —— 顺序敏感，逐条对应上文事实编号
def main():
    multiprocessing.freeze_support()          # 第一行：PyInstaller 必须 / Nuitka 无害（F3）
    if argv[0] == '--cli':                    # 子命令分发：承接 web spawn 的 CLI 入口（A1/F5）
        return cli.run_config.main(argv[1:])
    if frozen:                                # onedir 下 sys.executable 所在目录 = 安装根
        os.environ.setdefault('MS_STATIC_DIR', join(exe_dir, 'static'))   # F7
        os.environ.setdefault('MS_OUT_DIR',
            join(os.environ['LOCALAPPDATA'], 'MaterialSorting', 'out'))   # F1：用户数据可写区
    port = find_free_port(8010)               # F2：8010 被占则 +1
    os.environ['MS_WEB_PORT'] = str(port)
    if already_running(port_probe_or_mutex):  # 单实例：二次双击只开浏览器不起第二份服务
        webbrowser.open(...); return 0
    threading.Thread(uvicorn 启动)             # 延迟 import web.server（A4：env 先行）
    webbrowser.open(f'http://127.0.0.1:{port}')
    join()                                    # 控制台窗口关闭 = 进程树退出
```

要点：

- **import 顺序是正确性红线**：launcher 顶部只 import 标准库，`web.server` 延迟 import —— 因为 `paths.py` import 期固化路径（A4）、`server.py` import 期 mount + 读 intermediate（F7/F8）。
- `MS_DATA_DIR` 可不设（`data/configs` 仅示例配置，客户动线不依赖）；`MS_FONT_DIR` 走缺省包内路径即可（F6）。
- 关窗退出：控制台进程是整棵进程树根，Windows 关窗默认终止根进程；uvicorn 建议以非 daemon 线程/子进程持有，保证求解中强退不留孤儿（可加 CTRL_CLOSE_HANDLER 优雅停，v1 可不做 —— 与现网 kill 语义一致）。

### 3.3 唯一硬代码改动：CLI spawn 适配

现状两处（A1）spawn `[sys.executable, '-m', 'materialsorting.cli.run_config', ...]`。适配：

```python
# 新共享 helper（web 包内，strategy/machine 两处调用）
def cli_spawn_prefix() -> list[str]:
    if getattr(sys, 'frozen', False):
        return [sys.executable, '--cli']      # 冻结 exe 子命令（launcher 分发承接）
    return [sys.executable, '-m', 'materialsorting.cli.run_config']
```

- 改动点：strategy.py:963、machine.py:522 两行构造处 + helper 本体；`_spawn_run_process`、marker/run_dir 认领、taskkill `/T` 树杀、orphan 恢复全部零改动。
- 回归面：[test_web_strategy.py:324](../../materialSorting-server/tests/test_web_strategy.py#L324)、[test_web_machine.py:371](../../materialSorting-server/tests/test_web_machine.py#L371) 现断言 `cmd == [sys.executable, '-m', ...]` —— 保留（未冻结路径逐字节不变），新增 frozen 假标志单测锁新分支。

### 3.4 用户数据目录布局（安装目录只读安全）


## 四、构建流水线与发版

### 4.1 构建机一次性准备（我们侧）

1. Windows x64 + MSVC Build Tools（Nuitka C 编译后端）+ 本仓 venv（`py -3.11`）。
2. spyrrow 私有 wheel 就位：`scripts/spyrrow_wheel.py use-local <wheel>`（注意：**打包锁私有 wheel `+ms1`**，锁错会静默失去 warm-start，与 A2 同源，验收清单含 SE 延长轮 warm 生效检查）。
3. Inno Setup（ISCC 编译器）+ 代码签名证书（见风险 R1）。

### 4.2 构建脚本步骤（一键 `scripts/build_release.py` 或 .ps1）

```
1. 前端：cd materialSorting-web && npm ci && npm run build        → static/
2. 依赖：venv 安装 -e .[web]（spyrrow 已 use-local 锁定）
3. 冻结：nuitka --standalone --onedir
        --include-package=materialsorting
        --enable-plugin=<numpy/shapely/matplotlib 对应插件或 package-data>
        --include-distribution-metadata=spyrrow                  ← A2 红线
        --include-data-dir=<(repo)/materialSorting-web/static=static>
        --company-name/--product-name/--file-version=<版本资源，杀软友好>
        --windows-console-mode=force                              ← 保留控制台
        入口 = materialsorting/launcher.py
4. 冒烟：dist 目录拉起 launcher，跑既有 smoke 脚本族（smoke_prefix_extra / smoke_state_file /
        smoke_edit_polish 指向本地端口）
5. 安装包：ISCC 打 Inno Setup 脚本 → MaterialSorting-Setup-<ver>.exe
```

版本管理：产物版本号与 git tag 绑定写入 exe 版本资源；发版 = 打 tag → 跑脚本 → 归档安装包。

### 4.3 干净环境验收清单（每版本必过）

- [ ] 无 Python 的全新 Windows 虚拟机/新用户账户安装运行（per-user 免 UAC）
- [ ] 双击图标 → 浏览器自动打开 → 上传母版 → parse 预览 → 普通求解（WS 帧）→ 导出 PLT-clean / DXF / PNG（PNG 覆盖 A3 matplotlib 路径）
- [ ] **高级运行 + 极限运行端到端**（覆盖 A1 spawn 适配 + 子进程树 + run_dir 产物落在 LOCALAPPDATA）
- [ ] SE 延长轮 warm 生效（覆盖 A2：`importlib.metadata` 元数据捆绑，验 signature = ext 首帧即冠军密度）
- [ ] 状态保存/恢复（.msn 下载→重传→恢复会话）
- [ ] 端口占用回退（预占 8010 再启动）；二次双击不重复起服务只开浏览器
- [ ] dist 内 grep 无 `.py`/`.pyc`/`.docs`/`tests/`/`scripts/` 泄漏（源码保护验收）
- [ ] 360 / 火绒 / Defender 默认配置下安装+运行不误报（签名后复测）

## 七、需求 3 骨架（占位 —— 1/2 落地后单独 PRD，此处只定方向）

- **签发/消费分离**：服务器侧签发台（Ed25519 私钥）产 license 文件 `{客户标识, 机器指纹?, 到期时间, 次数配额, 版本范围, 签名}`；客户端仅内嵌公钥，**离线验签**（工厂内网现实，按离线优先设计，联网对时/激活为增强项）。
- **植入点 = 求解入口闸**而非 HTTP 层：`solve_pieces`（WS/machine 路径）+ `cli.run_config.main`（策略/极限子进程路径）双闸，覆盖全部算力消耗点；失效 = 拒绝求解并给中文指引，UI 只读功能不受影响。
- **时限**：水位文件防时钟回拨（last-seen 时间戳单调 + 联网时校准）；**次数**：本地加密计数，与验签同模块落盘。
- **强度边界**：与需求 1 同源 —— 编译后二进制内嵌闸门，逆向绕过成本高但非不可能；对授权客户与配额管控足够，不做内核级反调试。
- 已有工程先例可复用习惯：machine API 的 `MS_MACHINE_TOKEN` 常量时间比较（[machine.py US-005]）、`spyrrow_build.json` 钉板模式。

## 八、开放决策点（建议均已给出，可推翻）

1. **壳形态**：v1 控制台 + 浏览器（建议：简单可靠、日志可见）vs 直接 pywebview 原生窗口（v2 升级项）。
2. **分发形态**：Inno Setup 安装包（建议）vs 绿色 zip（可两者都出，同一 dist）。
3. **代码签名证书**：建议采购 OV（预算内最优解）；若暂缓，R1 风险自担并准备申诉流程。
4. **machine API（YL 对接）是否随本地版启用**：技术上随包可用（token 闸已在）；商业上是否暴露给客户另议。

## 附：与《多seed并发与部署架构_分析》§五的衔接

该文档（2026-08-14）已论证：exe 本地部署 = 每客户一个独立后端进程 = 各自独立的 state/intermediate/线程池，**从根上消除多用户并发与多租户风险**（106 多实例互杀同类问题不存在）。本方案是该结论的工程落地路径，并发安全论证不再重复。
