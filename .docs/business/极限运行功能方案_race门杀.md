# 极限运行功能方案：race 门杀 × 极限参数（v1.1，核心决策已确认）

> 2026-08-29 · 依据 [.docs/business/极限利用率实验报告_5336_pct与早终止.md](极限利用率实验报告_5336_pct与早终止.md)
> 及门判别力补充分析（本文 §2.3）+ 25-seed 池 E[max] bootstrap（§2.5）。
> 范围：**先只做 race 门杀**（se 延长臂明确排除在外）。

## 1. 功能定位

「高级运行」用 race 门杀在**给定总预算**内拿更高期望利用率；「极限运行」把同一门杀机制
搬到**极限参数**上，目标从「期望最优」换为「best-of-k 右尾最优」——即实验已验证的
92.0% 路径的工程化封装：

| 维度 | 高级运行 race（现行） | 极限运行（本功能） |
|---|---|---|
| solver_opts | 默认（p0.8/et1） | **p0.7 / et0 / workers 4 / depth 4（缺省）固定** |
| 每 seed 预算 | 180s | **600s**（可选 1200s） |
| 门位置 | 90s（τ=0.5） | 300s（τ=0.5，复用公式） |
| seed 流 | config seeds + 递增补齐 | 同（`strategy_seed_stream` 复用） |
| 判杀规则 | bar=门值历史 max（含被杀者）、严格破纪录续跑、首 seed 豁免 | **逐字复用 `decide_race_kill`** |
| 预算再投资 | 串行队列自然吸收 | 同 |

## 2. 数据依据（全部来自本实例实测，零外推）

### 2.1 极限参数（实验报告 §3）

`p0.70/et0` 相对默认 best +0.46pt（两杠杆叠加 90.42→90.67），seed 池 25 个 + 2400s 长跑
终局 92.005%。et0 强制吃满 + 0.7 切分是 et0 下的平衡点（探索吃满挖右尾、压缩留 30% 兑现）。

### 2.2 race 机制代码完全可复用

`decide_race_kill` / `race_plan` / `strategy_seed_stream` 均为纯函数（无 I/O），换
`race_budget=600` 即用；`--strategy race` 与 `--solver-opts` 同给已冒烟实证兼容
（pctprobe_race_et0：per-seed opts 正确透传、门杀正常运作）。

### 2.3 门判别力随预算档的量化（本功能的关键约束）

| seed 预算 | 门位置 | n | Spearman(门值,终值) | 冠军门排名 | 门杀回放冠军存活 |
|---|---|---|---|---|---|
| **600s** | 300s | 20 | **0.916** | 1/20 | ✅ |
| **1200s** | 600s | 15 | **0.896** | 3/15 | ✅ |
| 2400s | 1200s | 5 | **0.300** | 4/5 | ❌ 冠军被误杀 |

机制：et0 下改进后置（t_sat/T≈0.99），预算越长最终排名越由「后程爆发力」决定——
seed 8 正是门排名 4/5、终值 92.005 的被误杀案例。**⇒ 硬边界：极限运行 seed 预算上限
1200s；2400s 级冲刺不交给门杀管**（未来若要，走 se 冠军延长思路，超出本版范围）。

### 2.4 门杀吞吐红利

600s 档回放 20 seeds 存活仅 3：~85% seed 只消费门段（302.5s 名义）而非全程（602.5s），
同总预算下可试 ~1.7× seeds——正反馈到 best-of-k 右尾（第一杠杆）。

### 2.5 轮数收益曲线（25-seed 实测池 bootstrap，20000 次抽样）

| 轮数 n | E[max] | P(≥90.5) | P(≥91.0) | P(≥91.5) | race 期望耗时* |
|---|---|---|---|---|---|
| 5 | 91.167 | 0.96 | 0.61 | 0.37 | 0.6h |
| 10 | 91.452 | 1.00 | 0.89 | 0.65 | 1.0h |
| 15 | 91.610 | 1.00 | 0.98 | 0.85 | 1.5h |
| **20** | **91.709** | 1.00 | 1.00 | **0.97** | **2.0h** |
| 25 | 91.774 | 1.00 | 1.00 | 1.00 | 2.5h |

*期望耗时 = 602.5 + (n−1)×347.5s（首轮全程 + 后续每轮 0.85×门段+0.15×全程）。
n=25 恰好抽干整个池子（确定性 = 池最大值 91.774）；n>25 无法从 25 池外推新右尾
（bootstrap 有界），2400s 实验证明右尾未枯竭（92.005）但只能定性「更多轮不亏」。
**拐点 n≈20：再翻倍预算只买 +0.07pt 期望、+3pp 命中率。**

### 2.6 quadtree_depth A/B：维持缺省 4（2026-08-29 补充，调优不成立）

d3/d5 × seeds 0-9 × 600s @ p070/et0/workers4（对照 = 同 seed 既有 depth4 数据）：

| 臂 | 均值 | 门判别力 ρ | 冠军门排名 | race 回放交付 best |
|---|---|---|---|---|
| **d4（采纳）** | 89.896 | **0.976** | 1/10 存活 | **91.517** |
| d3 | 90.276 | 0.636 | 1/10 存活 | 91.263 |
| d5 | 90.450 | 0.794 | **4/10 被误杀** | 90.744 |

均值层 d3/d5 各 +0.38/+0.55pt 但 n=10 不显著（t≈1.1/1.4），且 **race 语义下反转**：
d5 冠军（91.174）门值 90.07 < bar 90.50 被误杀、交付垫底；d4 冠军门排名 1/10 干净存活。
race 交付 best：d4 > d3 > d5。**⇒ quadtree_depth 不进 opts（用缺省 4）**，全部标定
数据与 depth=4 自洽。详见实验报告 §6.1。

## 3. 功能设计

### 3.1 CLI 层：`--extreme` 糖衣旗标（ms-run-config）

```
ms-run-config <cfg> --extreme [--time 总预算] [--extreme-budget 600|1200]
```

展开为（缺省值固化，用户不可改 pct/et——极限参数是实验结论不是可调项）：

```
--strategy race --race-budget <extreme-budget 默认 600> --race-gate 0.5
--solver-opts '{"exploration_pct": 0.7, "early_termination": false, "num_workers": 4}'
```

（quadtree_depth 不写 = 缺省 4，§2.6 已验证调优在 race 语义下不成立。）

- 与 `--strategy` / `--kill` / `--solver-opts` / `--rotate-opts` 显式同给 → 退出 1
  （参数冲突，糖衣旗标独占策略与旋钮）；
- `--extreme-budget` 仅收 600 / 1200 两档（其他值退出 1——2400s 以上是 §2.3 硬边界）；
- 最低总预算：600 档 ≈ 905s（首轮全程 602.5 + 一轮门段 302.5），`race_plan` 现行报错即可；
- `--target` / `--lns` 共存行为与现行 `--strategy` 相同（R0 优先 / race 下 warn 跳过）。

### 3.2 Web 层：「极限运行」独立按钮（与高级运行同级，已确认）

- UI：主界面**独立「极限运行」按钮**，与「高级运行」并排同级（不进高级运行的
  race/se 模式选择）；独立弹窗 = 总时长预设（1h / 2h / 4h / 8h + 自定义）+
  实时展示「预计 ~N 轮 seed」（按 §2.5 口径估算：首轮 602.5s + 后续 ~350s/轮）；
  solver_opts（pct/et/workers）完全不暴露（已确认）；
- 后端：独立路由 `/api/extreme/*`，内部复用 strategy 运行时骨架（spawn
  `ms-run-config --extreme --time <T>` 子进程、产物清理、run_dir 认领）；run_name
  `web_<sid6>_extreme_<rand6>`（沿用 sid 前缀隔离约定）；
- **单飞槽与高级运行共享**：同会话二者互斥（409）——服务器 CPU 有限，避免同会话
  两个长跑子进程（4+4 workers）互相拖垮；跨会话仍各自独立（多会话 US-004 语义不变）；
- 结果轮询/停止/结果态展示：与现行高级运行完全同构（复用）。

### 3.3 产物与统计

- run_dir / result.json / curve / kill_decisions.jsonl：全部沿用现行 strategy 产物结构
  （race 判定行已含 bar/S_tau 字段）；
- `run_stats.jsonl`：config 段 additive 加 `"extreme": {"budget": 600}`（class_key 不变，
  与历史 run 可比性不受影响）。

## 4. 决策点（已确认 2026-08-29）

1. ✅ **seed 预算 = 600s**（门判别力最强 ρ=0.916、吞吐 ×1.7）；1200s 档暂不开放
   （右尾略深但成本 ×2、判别力降，性价比不敌多轮）。
2. ✅ **pct/et 对用户完全隐藏**（是实验结论不是可调项，暴露会诱发随手调参破坏
   已验证组合）。
3. ✅ **web UI 本期一起做**（独立按钮，与高级运行同级，见 §3.2）。
4. ✅ **验收判据 = 同总预算 4h 三臂对拍**：`--extreme` vs 现行 race 默认档 vs 均分
   600s×N seeds，三臂 best 密度 + E[best]（曲线库离线回放先行，端到端各跑一晚）。

**总时长默认值（待最后拍板）**：推荐 **2h**（≈20 轮，§2.5 拐点：E[max] 91.71、
97% 命中 ≥91.5pt，再翻倍只买 +0.07pt）；UI 预设 1h / 2h（默认）/ 4h（验收档）/
8h（挂夜），自定义下限 905s（race_plan 最低总预算，低于此 CLI 报错）。

  `_parse_prefix` 校验 → config 写键，CLI 链路本就模式无关）；迁移性复验口径 =
  960s 最小档真跑跑通端到端，长 AB 留待实际使用观察，极限参数（p0.7/et0/w4/
  600s）在 band/prefix ON 下的增益结论未复验**】**
- quadtree_depth 调优（**已 A/B 并关闭**，§2.6：race 回放 d5 冠军被误杀、交付垫底）；
