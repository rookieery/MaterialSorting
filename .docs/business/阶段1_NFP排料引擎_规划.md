# 阶段 1：带约束 NFP 排料引擎 —— 代码规划

> **定位**：阶段 0 证明"无 NFP 嵌套的 BLF 只有 56%，连人工 93% 都达不到"（见 [阶段0报告](../_output/bounds/report.md)）。
> 阶段 1 的目标：用 NFP 嵌套引擎把利用率推向人工 93%（方向 A），并为 95%（方向 B）打底。
>
> **状态**：待用户确认。确认后再写代码。
> **吸收用户两条建议**：①GPU 加速 ②裁片类型特化。

---

## 0. 对用户两条建议的可行性评估（诚实）

### 建议 ②：对固定类型裁片做特殊处理 —— **高可行、高价值，作为架构核心**

这是本阶段最关键的洞察。它把"通用 NFP 难题"变成"对固定片型离线算一次的模板"：

- 牛仔裤裁片类型固定（10 类），同类形状跨码只放码缩放（相似变换）。
- → 可**离线预计算**每对片型的最优嵌套模板（前+后头尾相对、腰+腰并排、机头贴后片…），在线排料直接组合模板，不重复算 NFP。
- 模板 = **版师经验显式编码**，正是技术分析里说的"产品护城河"。
- 跨码：模板存的是相对几何关系，对所有码近似适用（缩放不变）。

**这就是 DeepNest/ET 等通用引擎没有、而我们能有的优势**——我们是牛仔裤专用，可以把版师 know-how 固化进模板库。

### 建议 ①：GPU 加速 —— **硬件具备，但需"位图化"改造，有实现成本**

诚实说：排料的核心计算（NFP 是计算几何/Minkowski 差）**不是 GPU 的传统强项**（DeepNest/libnest2d/SVGNest 全是 CPU，不是巧合——计算几何分支密集、内存访问不规则）。但有一条可行的 GPU 路线：

- **位图化 NFP**：把裁片栅格化成 2D 张量，用 2D 卷积/相关（GPU 强项）一次性算出所有"无碰撞放置位置"。把几何问题转成张量问题，GPU 擅长。
- 你的 4080 16GB 能扛高分辨率位图（0.5mm/pixel，满足 v0.3 的 0.4mm 重合精度）。
- **GPU 最适合的两处**：①离线预计算模板库（大批量片对，GPU 并行）②在线 SA 多候选方案评估（batch 位图）。
- 代价：位图化有分辨率损失，需"位图粗搜索 + 精确几何精修"两段式补精度。

→ **结论**：GPU 可用且硬件好，但不是"把 CPU 代码搬上去"，而是借"位图化"这条路。好在建议②的"模板化"让 NFP 主要发生在**离线**，正好是 GPU 大显身手的地方。

## 1. 核心架构：模板化排料（两条建议的融合）

```
┌─────────────────────────────────────────────────────────┐
│ 离线层（一次性，可慢，GPU 主力）—— 建议②+①              │
│  对 10 类裁片两两组合，预计算嵌套模板                    │
│   · 位图化 NFP（torch GPU）找最紧嵌套位置                │
│   · 精确几何精修（numpy 多边形相交）                     │
│   · 产出：template_library.json（每对的相对位姿+合并bbox）│
├─────────────────────────────────────────────────────────┤
│ 在线层（排料时，要快，2min 目标）                        │
│  1. 模板组片：把裁片按模板合成"块"（前+后=1块…）         │
│  2. BLF 排块（块少，远快于排 128 片）                    │
│  3. SA 优化（模板选择 × 块顺序；GPU 并行评估多方案）      │
│  4. 约束层校验（v0.3 全约束）                            │
│  5. 导出 DXF/SVG（复用阶段 0 的 export）                 │
└─────────────────────────────────────────────────────────┘
```

**为什么这样能突破 56%**：阶段 0 的 BLF 失败在于"大裁片单列竖排"。模板化让前+后片预先头尾相对嵌套成块（裆弯互补），块的宽度/高度远小于两片各自之和，排块时就能像版师那样紧凑排列。

## 2. NFP 内核选型（基于环境调研）

环境：numpy ✓，shapely/scipy/torch/cupy/pynest2d 全缺，GPU=RTX4080S 16GB。

| 方案 | 评估 | 取舍 |
|---|---|---|
| libnest2d/pynest2d | C++ 成熟但 pynest2d 编译难、约束层外挂 | ❌ 放弃（编译+约束成本高）|
| shapely 精确 NFP | 凹多边形 Minkowski 实现复杂、单线程 CPU | ⚠️ 仅用于精修 |
| **位图化 NFP（torch GPU）** | 对凹凸都行、GPU 并行、精度可控 | ✅ **主方案** |

**主方案**：位图化（torch GPU）粗搜索 + 纯 numpy 多边形相交（阶段0已有 `_poly_overlap`）精修。

## 3. 约束层（v0.3 规则，套在模板+排块上）

裁片 IR 增加 v0.3 字段（[排料规则_详细版.md](排料规则_详细版.md) §3.2）：

| 字段 | 值 | 模板/排块如何遵守 |
|---|---|---|
| `allowed_orientations` | {0°,180°} | 模板只在 0°/180° 组合里搜 |
| `rotation_tol` | 各片公差 | 模板允许 ±tol 微调 |
| `max_overlap` | 外0.4~2 / 内5~10mm | 位图化时按对手 max_overlap 收缩轮廓 |
| `pair_key` | 成对类 | 模板优先配对同码 L/R |
| `grain_locked` | 水平 | 已在 load_pieces 对齐 |
| 内/外分类 | 见 v0.3 | 内部裁片可塞缝，外部不重合 |

## 7. 风险与开放问题

| 风险 | 缓解 |
|---|---|
| 位图化精度（0.4mm 重合公差） | 0.5mm/pixel + 精确几何精修；1a 验证误差 |
| torch CUDA 安装失败 | 退而用 numpy + FFT（纯 CPU 位图化，慢但可行，1a 同样可验证）|
| 模板库覆盖不全（某对片型没好模板） | 无模板时退化为单片 BLF（阶段 0 已实现，兜底）|
| SA 在线不达 93% | anytime 架构保底输出当前最优；版师经验持续补模板 |
| 跨码模板误差（大码形状略变） | 关键码（最小/最大/中）各算一套模板，中间插值 |
