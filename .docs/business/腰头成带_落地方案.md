# 腰头成带（建议2）落地方案

> 2026-08-21 定稿。依据：planner 全量代码规划 + 主分析工作流（11 agent：3 Recon / 3 Analyze / 批判轮）+ 核验工作流（6 agent：4 路代码断言 / 探针数字复核 / 设计批判，全部断言按证据裁决）。
> 版师建议2原文：「腰也排一起好些，大小穿插缝隙会大」。本文档是算法层落地方案；腰头 g 码由用户在 UI 指认（跨母版漂移：5336=g05，M1787 映射=g09）。

## 0. 性质判定与总原则

- **成带是业务规则，不是利用率优化器**：腰片聚排的密度收益未被证实（朴素拼接实测 −1.38~−1.59pt；「聚=省布」在单订单双 seed 配对下证伪，但差距 < seed 方差，非显著）。自发聚排是高方差涌现（同配置 seed0 尾带 span 1172mm / seed1 打散 5497mm），版师要的是**确定性形态**。
- **验收哲学**：形态保证是构造性的；密度只设「不显著劣化」接受线（A/B 同配置 ≤1.0pt），不承诺提升。
- **机制**：虚拟组合片（composite piece）——腰头类先独立小求解聚排成高密度簇，整簇 union 外轮廓当作一片投入主求解，帧发射前在子进程内展开回成员 placement。刚性「独占段拼接」已被实测否决（−8.66pt 代理集合），不走。

### 1.2 几何事实

- g05（5336 真腰）：bbox 183.4×1160.7mm、面积 82,202.7mm²、**面积/bbox ≈ 38.6%（弧形）**，172 顶点；demand=2×7 码=14 条；per_type {d:0.4, tol:3}；存储朝向 x=183/y=1161、grain 锁定（±3° 内不可 90° 转）。
- 带内 bbox 填充率可达上限：同码零间隙理想贴触 84.8%；异码实际贪心链 ~66.4%；自然解 ~70%。**任何 ≥85% 的判据数学上不可达。**
- 裤耳 g06（559×30、area/bbox=1.0 矩形）成带 = 13.08% 灾难；形状启发式护栏与适用性**反相关**（矩形完美填充恰是最差候选）。
- 版师文档在案硬规则：「腰成对，两个腰头一起排」（排料规则_详细版 L35）；现状全线不满足（最好 3/6 码成对相邻）。

## 2. 机制设计（核验修订版）

### 2.1 带几何（推翻 planner 窄条带设定）

~~窄条带 h_band=366mm(2 行)~~ 与 grain 锁定 + 1161mm 成员长**直接矛盾**（成员长轴是 y 向，塞不进 366 高条带；转 90° 违反 ±3° 且改变拉伸方向需版师签核）。修订：

- **band 子求解直接用全幅 `NEST_GATE_MM`**（= P3 唯一实测过的配置），解完裁剪到实际占用 bbox；
- h_band/rows 是**输出**不是输入；组合片 = 全幅解的 union 轮廓裁剪归一化；
- **默认整带单 Item**（~1.25m 宽 × ~1.33m 高 comb 形，自然解形态，保「一批在一块」捆扎语义）；仅当 comb NFP 微基准不过关才退到 **pair-atomic 分块**（块边界永不切开同码对）。

### 2.2 成员移出主实例（阻断 density 口径事故）

**禁止**用 quantities=0 移除腰片（会同时抹掉 pid_meta、total_area 与 manifest 腰片 → 密度掉 ~12pt、前端副本池丢片）。修订：`build_instance` 的 **Item 构造层**加 `exclude_labels` 类参数——只跳过 spyrrow Item，pid_meta/total_area/manifest 原样。单测：band on/off 下 manifest 的 total_area 与 pieces 列表逐字段一致。

### 2.3 展开数学（权威式，黄金单测锁死）

成员带内足迹 `P_band = R(m.rot)·p + m.tr`；组合片多边形 = union 足迹平移归一化（`P_comp = P_band - offset`，offset=(minx,miny) 为 union bbox 最小角）；主解放置 `P_world = R(c.rot)·P_comp + c.tr`。合并：

```
rot_f = m.rot + c.rot
tr_f  = R(c.rot)·(m.tr − offset) + c.tr        # offset=(minx,miny)，注意是减号
```

与 PlacedItem docstring（先绕原点旋转再平移）、`sparrow_baseline._transform_polygon`、`export_geometry.apply_transform`、前端 `lib/geometry.ts` 四处同构。展开在 `_emit_placed` 单点挂；组合片 pid（`WB_*`）永不出现在 manifest/frame/final/导出（泄漏哨兵：grep 后端日志「导出跳过：pid」）。

### 2.4 成对规则进 v1（几乎免费）

成员 **size-major 排序**进带（同码相邻）+ 分块时 pair-atomic + 验收指标「同码两条成员中心距 ≤ 阈值」+ QtyMatrix 奇数 demand 时 UI 警告「该码不成对」。

### 2.5 带内求解与确定性

- 成员 Item 用 pid_meta 已腐蚀多边形（不二次腐蚀），orientations = discretize_orientations(tol_g)={0,180}±3°；组合片 orientations=[0.,180.]（不带抖动：±3° 使 1.25m 块 bbox 膨胀 ~65mm 且产生斜缝；工艺公差属于裁片不属于带）。
- 组合片轮廓 = `shapely.unary_union(成员原轮廓@带内位)` → `erode(d_g)` → `_clean_polygon` → 平移归一化；顶点超预期时 `simplify(0.05)` 预处理。
- 预算：与 fill 曲线挂钩（fill 不随预算增长即停），初值 15s/带 + 30s 总上限；**禁止无声 shelf 兜底**——异常时 fail-fast 报 error。
- 确定性：band seed = `zlib.crc32(f'{seed}|{label}')`（多 seed 连接各自派生）；验收口径 = placed_items/density 序列逐帧相等（**不是** byte-identity——帧内嵌 wall-clock elapsed）；band 几何工件落 `out/band_runs/*.json` 供回放对拍。

### 2.6 进程模型（防孤儿孙进程）

band 子求解**以线程方式跑在 solve_worker 进程内**（复用 `solve_with_progress` 线程骨架，不用 `solve_with_callback_proc` 再 spawn）——`_terminate_solve_process` 的 terminate 不级联孙进程，线程版被 terminate 直接回收。测试：band 阶段 stop 后无存活 python 子进程。

### 2.7 stage 消息（不再是可选）

`{'type':'stage','stage':'band', fill_pct, bbox, fallback:false, elapsed}` 固定携带统计；fill_pct < 45% 时 fail-fast error（无声降级 = 质量悬崖）。旧前端 default:break 静默忽略，前向兼容。

### 2.8 误选护栏（经验式，非形状启发式）

① 服务端校验 band 键（label 存在、该 g 码 quantities>0、奇数 demand 警告），非法回结构化 error；② 最小边 <60mm 或长宽比 >6 的 label 需 StartPayload 显式 `band_ack` 才执行；③ 确认弹窗回显带内预求解实测 {fill, 带尺寸} 对照 break-even 参考线（draft 阶段服务端真跑一次，复用 /api/ptypes 缩略图底座）。


## 6. 已知风险

- 主解对大 comb Item 收敛变慢（US-010 微基准把关；不过则 pair-atomic 分块）。
- 纯腰组合片带内 54.8~60% < break-even——带本身净亏损，靠板外围邻接 + 端部开口部分回收，全局目标仅「≤1pt 劣化」；真正拉平要等 v1.1 混填料。
- 生产基线不同构（d=0.0/uploads 源/kill 跑法）——A/B 必须同源同构对照，勿跨口径下结论。
