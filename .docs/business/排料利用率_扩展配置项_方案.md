## 〇、一句话结论

当前引擎只用了 spyrrow `StripPackingConfig` 的 3 个参数（`total_computation_time` / `seed` / `num_workers`），**至少还有 4 个原生旋钮（compression 时间占比、`quadtree_depth`、`min_items_separation`、`early_termination`）零成本可试、当前完全未暴露**。按性价比，**最该先动 compression 阶段时间占比**（直接关系最终用布宽度），其次吃满 `num_workers` / 关 `early_termination`、调 `quadtree_depth`。建模层的"顶点精度"与"镜像配对策略"是中期高 ROI 方向。求解器算法本身与分区排料触碰"不改 sparrow 源码"红线，是天花板。

## 一、背景：两个已落地杠杆的机制回顾（基线）

旋转与重合是当前唯一接入的两个利用率杠杆，**两者都在 `build_instance` 阶段一次性"烘焙"进喂给 spyrrow 的几何输入，sparrow 运行时不感知"公差"概念**（这正是 CLAUDE.md "v0.3 约束在外层包装实现、不改 sparrow 源码"决策的具体落点）。

| 杠杆 | 改变的对象 | 实现手段 | 归属 | 代码 |
|---|---|---|---|---|
| **重合 d** | 裁片**形状**（变小） | shapely `buffer(-d)` 向内腐蚀 | 外层 shape | `web/solver.py:128-134` → `nesting_engine/sparrow_experiments.py:36-51` |
| **旋转 tol** | 裁片**姿态空间**（更多朝向） | `discretize_orientations` → per-item `allowed_orientations` | spyrrow Item | `web/solver.py:41-63, 136-161` |

### 关键认知（避免后续误判）

1. **重合 d 定型的是"上限"不是"实际量"**：腐蚀后 `poly'` 之间不相交 ⇔ 真实轮廓重合 ∈ [0, d]。相邻两片可相切（满重合 d）也可相离（重合 0），求解器按全局紧凑度自取。**不存在"每对固定重合 d"**。
2. **但 spyrrow 缺乏"主动留缝"激励**：在 `poly'` 世界留缝=浪费布，求解器本能挤紧 → 实际布局**倾向**满重合 d。d 是全局均匀腐蚀，**无法按片对/按边差异化**（如"这对目标 5mm、那对 10mm"）。
3. **旋转是 per-item、非全局**：`allowed_orientations` 挂在每个 `spyrrow.Item` 上，不同片型喂不同角度集，正好承载 v0.3"外部锁布纹线、内部多姿态"。三种取值：`None`=自由旋转 / 空序列=`[0.]` / 角度列表=离散限定。spyrrow 对角度集长度"非常不敏感"（38 个角度不降速）。
4. **重合与旋转实现路径不对称**：旋转借 spyrrow 原生能力（`allowed_orientations`）；重合是纯外层 trick（sparrow 无"允许侵入"开关，`min_items_separation` 只能要求留缝、不能允许重叠）。

## 三、第一类：spyrrow 原生但项目未暴露的 Config 旋钮（核心扩展点）

以下均在 `web/solver.py:165-166` 构造 `StripPackingConfig` 处接入（当前仅传 `total_computation_time` / `seed` / `num_workers=4`）。API 权威定义见 `.venv/Lib/site-packages/spyrrow/__init__.pyi:112-156`。

### 3.1 `exploration_time` / `compression_time`（最该先试）

- **现状**：只传 `total_computation_time`，spyrrow 按默认 **80% exploration / 20% compression** 自动拆（`.pyi:134-136`）。
- **机制**：spyrrow 两阶段元启发式（`.pyi:72-86` 的 `ReportType`：`ExplFeas/ExplInfeas/ExplImproving` 探索 + `CmprFeas` 压缩 + `Final`）。**exploration** 找可行解，**compression** 压宽度——而最终用布宽度（=利用率分母）主要由 compression 决定。默认只给 20% 偏少。
- **预期**：调成 `exploration 60% / compression 40%` 之类，**相同总时长下可能直接挤出更高利用率**。
- **落地**：`StripPackingConfig` 支持三选二传法（传 `exploration_time` + `compression_time`，或只传 `total`）。`web/solver.py` 改一行即可实验；要做成可配参数则再串前端 ControlPanel → `lib/params.ts` → WS payload。
- **验证脚手架**：`nesting_engine/sparrow_experiments.py` 本就是单变量对照实验脚手架，加一组"时间分配"实验很顺。

### 3.2 `quadtree_depth`（碰撞精度旋钮）

- **现状**：未传，默认 4（`.pyi:117,142`，common 值 3/4/5）。
- **机制**：底层 jagua-rs 碰撞引擎的空间剖分深度。depth↑ → 碰撞检测更精细。**间接**提升利用率：粗糙碰撞会"保守误判"两片重叠（实际没有），求解器不敢推紧；提高精度能释放这些被误判吃掉的缝隙。
- **预期**：方向上通常"depth↑ → 能排更紧"，但会拖慢单次碰撞判定。需实验找甜点（3 vs 4 vs 5）。
- **风险**：方向非单调确定，需实测；过深可能显著拖慢。

### 3.3 `min_items_separation`（与重合并存的全局间距约束）

- **现状**：未传，默认 `None`（`.pyi:119,144`）。
- **机制**：**Config 级**（全局）"片间最小距离"。注意它与项目用的"腐蚀"是**两套独立机制**：
  - 腐蚀改 **Item 的 shape**（每片不同，已实现重合）；
  - `min_items_separation` 是**求解器碰撞时的全局间距要求**。
- **方向**：设正值 → 强制所有片间留缝（**降低**利用率）。项目要的是"允许重叠"，故保持 None 正确。
- **扩展价值**：值得暴露——版师若要求"重合归重合，但某些片之间至少留 1mm 裁剪剪刀余量"，这是原生开关，不用再写外层 trick。它甚至可与腐蚀**叠加**（腐蚀 d 允许侵入 + separation 要求最小净距）。
- **注意**：它**只能要求留缝、不能允许重叠**（负值行为未在 stub 文档化，不能依赖）——重合仍必须走腐蚀。

### 3.4 `early_termination` + `num_workers`（把算力吃满）

- **`num_workers`**：当前写死 4（`web/solver.py:166`）。`.pyi:149` 说 `None` 时自动取逻辑核数。改 `None` 或更高 → **同等时间预算下 exploration 探索更多候选** → 更可能撞到高利用率解。
- **`early_termination`**：默认 `True`（`.pyi:113`）。开着 = 算法自认收敛就提前停，但"自认收敛"≠全局最优。跑多 seed、单次想榨干时**关掉**让它跑满预算，配合多 seed 取最优，是用算力换利用率的组合拳。
- **落地**：两个都是 Config 一行参数的事，扩展成本极低。`num_workers` 改 `None` 让 spyrrow 自适应核数最省心。

## 四、第二类：已接入的非旋转/重合杠杆（已可用，列此备忘）

这些前端已暴露或代码已接入，属于"现成可调"的利用率手段，无需扩展开发：

- **`total_computation_time`(time)**：元启发式 anytime，2min 出图，600s 收敛（见 [阶段2_90利用率突破_方案.md §6.1](阶段2_90利用率突破_方案.md) 实验①：600s→85.79%，3600s→85.81%，时间非瓶颈）。
- **`seed` / 多 seed(multi_seed, clamp 2-6)**：**破 90 主手段**。sparrow 对 seed 敏感（std 0.72pp），跑 N seed 取最优可稳定逼近 max（seed3 实测 90.38%，见主线方案 §6.3）。已实现。
- **`strip_height`(gate 门幅)**：利用率分母的一部分，更宽门幅可能让某些排法成立。工艺决定，非自由旋钮。
- **`sizes`(套排码号)**：多码混排是利用率提升的最大业务杠杆（版师 B 已限定码号客户定，组合空间受限）。
- **`demand`(quantities)**：需求量大的片有更多副本可"互相咬合"，影响排布密度。已实现 per-size demand。

## 五、第三类：外层建模扩展点（不改 sparrow 源码）

### 5.1 多边形顶点精度/简化

- **现状**：`nesting_engine/sparrow_baseline.py` 的 `_clean_polygon` 做了基础清理，但"精度档位"未参数化。
- **机制**：裁片曲线用多少段折线逼近，直接决定 NFP 几何精度与计算量。顶点太疏 → 轮廓"方"→ 相邻片咬合面粗糙、留缝；顶点太密 → NFP 爆慢、同时间预算下探索次数骤降。
- **落地**：按片型加"精度档位"参数（曲线细分 / Douglas-Peucker 简化），在 erode 之前的几何预处理层接入。
- **风险**：精度↔速度是 trade-off，需按 M1787 裆弯曲线复杂度找甜点。

### 5.2 镜像排布策略

- **现状**：`nesting_bounds/load_pieces.py` 把裁片成对镜像展开为 L/R 后，交 spyrrow 自由排，无配对约束。
- **机制**：镜像片"面对面 / 背靠背 / 平行"的配对方式是大利用率点（版师经验：前后片面对面套排是省布关键）。让求解器自由"发现"这种咬合不稳。
- **落地**：外层**预配对**镜像片——把它们当成组合刚体喂 spyrrow，或约束其相对朝向（用 `allowed_orientations` 联动）。不改 sparrow，工程量中等。

### 5.3 布纹线/裁向策略

- **现状**：`nesting_bounds/load_pieces.py` 固定布纹线水平对齐。
- **机制**：若允许多个布纹方向（如斜裁 45°），等于新增一维姿态空间，可能解锁更紧排布。
- **风险**：服装工艺上布纹线是硬约束（斜裁改变面料伸缩/纹理），**强业务约束**，需版师拍板，不可当纯技术旋钮。列此仅作"理论存在"备忘。

## 六、第四类：架构约束天花板（触红线 / 工程量大，仅标注）

- **求解器算法本身**（#16）：sparrow 的 CDE+GLS 两阶段策略固定。换求解器（纯 NFP 精确排 + 局部搜索）或调内部启发式权重是更大杠杆，但**触碰"不改 sparrow 源码"核心决策**（CLAUDE.md）。`gls_optimize.py` 自研 GLS 回退方案已搁置（见主线方案 §十）。
- **分区/分层排料**（#17）：先排大片区（前/后片）定骨架、再往缝隙填小片（袋/裤耳），这种"版师式"两阶段排法利用率天花板更高，但需在 sparrow 之上再造一层编排逻辑，工程量大。

## 八、风险与边界

1. **不改 sparrow 源码红线**：#16（求解器算法）是天花板，所有扩展都在此红线内做"参数 + 外层建模"。sparrow 的"排斥任何接触"设计与服装内外档重合冲突——重合永远必须走外层腐蚀，不能指望 sparrow 原生支持。
2. **spyrrow 0.9.0 < 1.0，API 不稳**（主线方案 §七 风险 2 已记）：`StripPackingConfig` 参数未来可能变动（已踩过 `num_workers` 坑）。新增参数接入需锁版本，必要时 vendor。
3. **方向不确定性**：`quadtree_depth`、`early_termination` 对利用率的影响非单调，必须实测验证，不能假设"调大就好"。
4. **业务约束前置**：#5 门幅、#6 码号、#15 布纹线受版师/客户决策锁定，不能当自由技术旋钮（见主线方案 §九 已决策点：不分床、码号客户定）。
5. **密度口径**：所有利用率数字用**原面积口径** `real_density = total_area/(width×gate)`（90% 生死线口径），spyrrow 自报 `density`（erode 后面积）仅参考。换算在 `web/solver.py:381-390` `_apply_density_dual`。
