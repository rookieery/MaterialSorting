# 排料 90% 利用率攻坚:思路与流程总结

> 时间:2026-08-06
> 起点:阶段 1c 利用率 71.9%;目标:90%+(产品生死线)
> 状态:**sparrow 基线 85.79% 已验证** → B 路径 2a 方案已确认 → **2a-1 代码实现中(有个 bug 待修)**

---

## 一、背景与核心问题

`material sorting/` 是排料(自动 marker making)模块。当前自研引擎(位图 FFT NFP + BLF + 弱 SA)在 M1787 直筒款 8 码套排 128 片上只到 **71.9%**,而生产场景要求 **90%+** 才能直接投用。差距 ~18pp。

用户要求:**先深度调研业界怎么实现,结合本项目场景给可行方案,确认后再执行**(不能埋头硬调)。

---

## 二、四个利用率锚点(全流程决策基准)

跑通数据流水线后,先钉死几个数字,后续所有判断都对照它们:

| 锚点 | 利用率 | 用布长度 | 含义 |
|---|---|---|---|
| 理论 100%(密铺) | 100% | 634 cm | 物理下界,面积/门幅 |
| **人工(版师)** | **93%** | 682 cm | 已证明可达 |
| 90%(生死线) | 90% | 704 cm | 产品门槛 |
| stage1c(当前) | **71.9%** | ~874 cm | 自研位图+弱SA |
| BLF 贪心(阶段0) | 56% | 1132 cm | 无嵌套下界 |

**总面积 12.55 m²,门幅 1980mm,前片+后片占面积 73%** → 利用率由大裁片嵌套决定,小裁片是填缝配角。

**第一性结论**:连版师手工都能到 93%,所以 90% **不是物理天花板问题,是算法问题**。

---

## 三、三路业界调研(核心发现)

派 3 个 agent 并行调研商业软件 / 学术界 SOTA / 开源引擎,交叉验证。

### 3.1 共识(三路一致)
1. **位图 NFP 是学术 SOTA 的反面教材**(精度上限 + 内存 + 无法表达非正交边,全撞牛仔裤曲线)
2. **正道 = 精确几何 NFP(Minkowski)+ 迭代改进(临时允许重叠)+ Guided Local Search**
3. **90%+ 不全是算法问题**,强依赖款型互补性 / 码号组合 / 面料约束
4. **现实目标 82–88%,stretch 90%+**;商业软件"90%+"多有营销成分

### 3.2 学术界(sparrow 2025,arxiv 2509.13329)
- {0°,180°} 约束下基准:**TROUSERS 92.6%**、SHIRTS 90.9%(开源 SOTA,首次公开 90%+)
- sparrow 范式 = "**临时允许重叠 + GLS 引导逐步消除碰撞**"
- **关键洞察**:这个范式与本项目 stage1c 的"重合公差排料(内外档允许重叠 5-10mm)"**思路完全同源**——已站在 SOTA 方法论上,只是实现降级了

### 3.3 开源引擎(逐一源码核查)
- **sparrow**:唯一开源 90%+,但设计**排斥任何接触**,与服装内外档重合冲突
- **libnest2d**:之前 memory 记的"最适合嵌入"**彻底推翻**(仅凸多边形、孔洞是 TODO、已停滞 2022)
- **pyclipper.MinkowskiDiff**:Python 生态精确矢量 NFP 的关键 primitive(NFP = Minkowski 差),现成函数,不用自研 Minkowski
- **DeepNest/SVGNest**:73-80%,缺服装四约束,弃维
- **关键结论**:所有开源引擎都**不支持服装内外档重合公差语义**,约束层永远必须自建

### 3.4 商业软件
- Lectra/Gerber/Optitex/富怡/ET **全封闭零 SDK**,"买引擎"市场不存在 → 反向验证自研必要
- 典型 82-88%,牛仔顶级 88%+
- 两个被低估的收益源:**cut-order 分床**(Lectra 单独卖 OptiPlan)、**多姿态放宽**(工艺侧决策)

### 3.5 一个被证伪的判断
商业路调研曾下判断"71.9% 已接近 {0,180} 约束的物理上界,要 90% 必须放宽姿态"。**这个判断后被 sparrow 实测推翻**(见 §六)。

## 四、瓶颈诊断的演进(初判 → 校准)

诊断经历了两次校准,这是本流程的方法论重点——**不靠拍脑袋,靠数据逐步收敛**。

### 初判(读代码后)
四个瓶颈:① 位图精度(2mm/像素);② 弱 SA(40 次/单邻域);③ 缺迭代范式;④ 预组块废弃。

**当时怀疑位图精度是主因。**

### 校准 1(学术界调研后)
学术界定性:位图是反面教材。但 sparrow 在 {0,180} 下到 92.6%,说明**约束不是问题**。主因权重待实证。

### 校准 2(sparrow 基线实测后,见 §六)—— **最终结论**
**主因不是位图精度(只占 1-2pp),是算法强度(占 14pp)**。第一刀应砍在优化器(GLS),不是 NFP 精度。

---

## 五、方案确立:B 路径(不换底座)

基于调研,有两条路:
- **A 路径**:换 sparrow 等开源底座 + 外挂服装约束
- **B 路径**:保留自研,把"位图+弱SA"升级为"精确NFP+GLS",学 sparrow 思想

**选 B,不选 A**,理由:
1. 所有开源引擎都不支持服装内外档重合,换底座 = 约束层推倒重来
2. 本项目护城河(v0.3 约束层 + 模板库 1b + GPU pipeline + DXF 解析)全在自研栈
3. sparrow 思想与"重合公差排料"同源,升级比替换自然
4. 工程量 B(2-3 月)< A(3-6 月),天花板相当

方案文档:`material sorting/阶段2_90利用率突破_方案.md`,B 路径分 6 阶段(2a GLS → 2b anytime → 2c 精确 NFP → 2d 多姿态 → 2e 组块填缝 → 2f 套排 GA)。

### 用户第一个决策点(AskUserQuestion)
选项:① 先跑 sparrow 基线验证 / ② 直接 B 路径 / ③ 换底座。
**用户选 ①**(成本最低、信息量最大)。

## 六、sparrow 基线验证(关键转折点)

这是整个流程的**实证转折**——用 1-2 天硬数字回答"90% 在 M1787 上到底可达吗"。

### 执行
1. `pieces_export.py` 把 128 片 dump 成中间 JSON
2. `pip install spyrrow`(Windows cp311 wheel,无需 Rust)
3. `sparrow_baseline.py` 转 sparrow 输入(JSON:128 item 各 demand=1,{0,180} 姿态,strip_height=1980)
4. 先单码 16 片 10s 验证流程通(顺带发现 spyrrow 0.9.0 参数名是 `num_workers` 非 agent 说的 `num_wokers`)
5. 后台跑全 128 片 600s

### 结果:**85.79%**(用布 739cm,460s 收敛早停)

### 三个结论(直接驱动后续)
1. **90% 接近可达但是 stretch**。sparrow 已是开源 SOTA,85.79% 是 {0,180}+无重合的几何上界。距 90%(704cm)差 35cm/4.2pp。M1787 几何天花板约 85-90%(低于学术 TROUSERS 92%,因真实裁片 199 顶点曲线更复杂)。
2. **算法强度是主因,14pp 损失印证诊断**。sparrow 85.79% vs stage1c 71.9% = +13.9pp = "位图+弱SA"相对"精确几何+GLS"的纯算法损失。**彻底证伪"{0,180} 上界说"**——同约束下 sparrow 到 85.79%,瓶颈是算法不是约束。位图精度只占 1-2pp。
3. **B 路径护城河被验证**。sparrow 排斥接触、没用服装重合公差就到 85.79% —— v0.3 内外档重合 5-10mm 是它白浪费的空间,B 路径加上后理论上能超 sparrow 到 88%。

### 目标校准(取代原方案的目标定位)
- **现实目标 88%**:精确 NFP + GLS + 服装重合公差(纯算法侧,2-3 月,不依赖版师)
- **stretch 90%+**:再加多姿态(v0.3 旋转公差)+ cut-order 分床(需版师确认)

### 用户第二个决策点
选项:① 开始 B 路径 2a(GLS)/ ② 先摸清 sparrow 上界 / ③ 先问版师。
**用户选 ①**。

## 七、2a 设计(plan mode,已确认)

### 7.1 深度提取 sparrow 算法(可复现 spec)
派 agent 读论文 + 源码,产出复现规格。**5 个颠覆性认知**(和当前实现完全不同):
1. **没有 SA、没有温度** —— 纯贪心接受,靠 GLS 权重动态放大跳局部最优(当前 sa_optimize 的 SA 温度范式是错的)
2. **cost 只有重叠 penalty 一项,没有"容器尺寸项"**;"shrink"是几何操作(右片左移制造碰撞再消除)
3. **片临时允许重叠** —— 转化为"一系列 feasibility 问题"(缩窄→必然重叠→最小化→归零→再缩窄)
4. 碰撞检测 ≠ 优化(几何外包给 CDE,优化器通过 4 个 API 调用)
5. 采样式搜索(随机采样 + coordinate descent,连续空间)

### 7.2 CDE 复用确认(Explore agent)
确认软碰撞 CDE 能直接复用现有代码,**不用从零写**:
- `block._xcorr(grid, bm)` 的 `corr[oy,ox]` 就是"片在 offset (ox,oy) 与 grid 的重叠像素数"——把现在 `pack_gpu` 里 `corr>0.5` 硬阈值去掉,corr 直接当软碰撞 cost。改动 < 50 行
- 重合公差复用 `constraints.erode_bitmap`
- **重大简化**:`_xcorr` 一次 FFT 算出全 offset cost 图,直接 argmin 选 min-overlap 位置——比 sparrow 的"采样+coord descent"更简单更快,**跳过 sparrow 最复杂的 perform_sampling 模块**

### 7.3 plan 要点(已 ExitPlanMode 确认)
- **新建** `gls_optimize.py`,**复用** `_xcorr`/`rasterize`/`erode_bitmap`/`load_pieces`
- 4 子步(验证式推进):
  - **2a-1**:软碰撞骨架(计数 grid + `_xcorr` 选 min-overlap + shrink-then-resolve + 贪心 separate)。里程碑:单码 ≥ 72%(不退步 = 范式可行)
  - **2a-2**:GLS 权重 + 探索/压缩两阶段 → 单码 ≥ 78%
  - **2a-3**:重合公差 + 多 worker → 单码 ≥ 80%、全量逼近 80%
  - **2a-4**(可选):pole of inaccessibility overlap proxy → 全量逼近 85%
- sparrow 参数照搬(R_EPS=0.01,M_U/M_L/M_D=2.0/1.2/0.95,shrink 0.001,K_X/N_X=3/200 等)

### 8.2 当前卡点(2a-1 的 bug,待修)
`gls_optimize.py` 单码 28 跑通了初始 BLF(45.37%),但 shrink 循环里 `_build_count_grid` 报错:

```
AttributeError: 'numpy.ndarray' object has no attribute 'to'
```

**根因**:`block._single_block` 的 `bitmaps` 存的是 **numpy 数组**,而 `_build_count_grid` 里 `bm.to(device)` 是 torch 方法。需要在用到 torch 的地方先 `torch.from_numpy(bm).to(device).float()`。

**这是个机械 bug,不影响设计**。修法:`_build_count_grid`、`_separate` 里所有 `bm.to(device)` 前加 `torch.from_numpy(...)`(或统一在 Block 构建时缓存 torch 版位图)。

### 8.3 初始 BLF 的一个观察
单码 28 初始 BLF 用布 157.6cm(利用率 45.37%),比 stage1c 全量的 71.9% 低很多——这是**单码无套排互补** + **BLF 本身就弱**(阶段 0 已知 56%)的正常表现。2a 的价值就是从这种弱初始解出发,靠 shrink+separate 压紧。

## 十、核心思路链(一句话串联)

> 72% 卡住 → 三路调研确认"位图是反面教材、90% 物理可达、开源都不支持服装重合" → 选 B 路径(自研升级不换底座) → 先跑 sparrow 基线实证 → **85.79% 证伪了"{0,180} 上界"说、定位主因是算法强度 14pp、验证了服装重合公差护城河** → 深挖 sparrow 算法发现"无 SA/纯贪心/GLS/shrink-then-resolve" → 确认 CDE 能复用 `_xcorr` 且 FFT 可替采样(跳过最复杂模块) → 设计 4 子步 plan → 实现 2a-1(卡在 numpy/torch 类型 bug)。

**两个最重要的认知翻转**:
1. {0,180} 不是 90% 的障碍(算法才是) —— 由 sparrow 85.79% 实证
2. 主因不是位图精度(是 SA 强度) —— 由 14pp 差距拆解

**一个护城河验证**:服装内外档重合公差是 sparrow 设计上放弃的空间,是本项目超它的杠杆。
